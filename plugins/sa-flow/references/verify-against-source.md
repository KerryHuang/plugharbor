# 驗證要看原物，代理指標得先證明它代表目標

> 跨 skill 通用原則。任何 skill 要「確認一件事成立」時適用，
> 交付前的檢查、退件後的複驗、以及呼叫端判讀 agent 回報時尤其適用。

## 問題的形狀

用一個**間接的量、標記或文字**代表一個事實，而沒有先證明那個中介物真的代表它。

中介物幾乎總是比直接看原物便宜——這正是它危險的地方：**便宜、看起來像在驗證、
而且錯的時候會靜默通過**。

在某次看板類功能的驗證中，同一個形狀在一輪內出現七次（另有三次跨鏈歷史）：

| 用的中介物 | 以為它代表 | 實際代表 |
|---|---|---|
| SQL 表 `COUNT(*)` | 畫面上有沒有東西 | 某張不相干的表有幾列 |
| inventory 上「已量測確認」標記 | 座標是對的 | 有人宣稱量過（實測差 105px） |
| caption 文字 vs 標註清單文字一致 | 圖文相符 | 兩份文字互相一致（雙方同時說錯就漏） |
| 框架語意色名 `positive` | 畫面是綠色 | 框架的分類名稱 |
| 「遮罩框內深色像素 0」 | 個資已遮掉 | 框住的地方本來就是白的（框歪了） |
| `sum(px) < 500` 判定「有文字」 | 該處有深色文字 | 連藍色底 `(49,128,253)` 都算進去 |
| 規則條文的字面擴大解釋 | 某類內容不得出現 | 範本其實明訂該類內容可以留 |

其中兩次發生在**已經知道前幾次教訓之後**——這不是知識問題，
是沒有機制強制在關鍵判定上看原物。

## 三條規則

### 1. 能直接看原物時，不要用代理

圖就開起來看、檔就讀出來、頁面就截下來。
「開圖看一眼」通常只比「跑個統計」貴幾秒，卻是唯一不會靜默失敗的方法。

**判準**：這個結論如果錯了，會不會有人受影響？會 → 看原物。

### 2. 非用代理不可時，先寫一句「它為什麼代表目標」

寫不出來就不要用。寫得出來，那句話本身也要能被反駁——
問「**在什麼情況下這個代理會通過、但目標其實不成立？**」

前表每一列都是這個問題沒被問。例如「框內深色像素 0」：
框沒對準目標時它必定通過，因為那裡本來就是白的。

### 3. 統計數字只能輔助，不能當結論

像素統計、字串計數、檔案大小、行數、mtime、`grep -c` ——
這些拿來**縮小範圍**、**定位可疑處**很好用，
但「確認它真的對了」那一步要回到原物。

## agent 回報的數字一律重算

agent 自報的量化數字與實測不符是反覆出現的模式，不限於特定 skill
（`linear-daily-report` 的抽樣筆數、`dev-readiness` 的自評範圍、
`manual-writer` 的字數與頁數）。**不是誰不可靠，是自報這件事結構上就沒有對照。**

- 呼叫端收到數字，**落檔或下判斷之前自己重算一次**。
- 派工時要求 agent 附上**可重跑的指令**，而不只是結果。
- agent 沒有 `Bash` 之類的工具卻被要求自跑腳本時，它會照實說做不到——
  **那句話要接住**，不要讓它變成沒人補的缺口。

## 缺席長得像成功

代理指標的近親：**「查不到東西」被當成「沒有問題」**。某次新舊畫面對照一案連踩六次——
比對器缺鍵時 `.get()` 回 0 而過閘；舊格式 run 檔沒有結構化欄位，`None == None` 判為一致；
`validate({})` 回空 list 當通過；同步工具的 glob 零命中判成「無變更」。

為什麼危險：預設值在正常路徑都對，錯在「缺席」與「合法的空／0」用同一個值表示，沒有任何錯誤訊息，結果還很漂亮。

- 寫比對／驗證／閘門工具：鍵不存在要**拋錯**並帶上哪條哪欄；null 或非預期型別也拋錯，不當 0。「沒記到」與「記到 0」是兩件事，只有後者能過閘。
- 比對兩份資料要有**期望集合**（來自權威來源），不用兩邊 union，否則雙方同時缺的看不見。
- 空輸入（`{}`、空 list）對驗證器是錯誤，不是通過。
- 測試做突變推理：「拔掉這個守衛，哪條測試會紅」；全綠也護不住一個 `or` 短路。
- 查詢回 0 筆，先懷疑路徑／鍵名／讀錯檔，再懷疑資料不存在。

## 這條原則不是「多加一層檢查」

再加一層檢查，只是多一個可能失效的中介物。
**方向是把驗證的終點換成原物本身**，而不是延長驗證鏈。
