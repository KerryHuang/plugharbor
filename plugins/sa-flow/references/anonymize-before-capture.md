# 截圖前換假資料，不要事後遮罩

> 含真實資料環境截圖的**預設做法**。由 `operation-manual` 的 S2a／S4 與 `manual-explorer` 指向。
> 工具：[`scripts/anonymize-page.js`](../scripts/anonymize-page.js)

## 為什麼改掉遮罩

遮罩是**事後**在 PNG 上塗色塊，代價全落在讀者身上：

| 遮罩的問題 | 實例（某看板頁） |
|---|---|
| 蓋掉版面，讀者看不出畫面原本長什麼樣 | 六個群組名稱遮完，清單只剩六個選項圓圈 |
| 蓋掉教學主體 | 卡片中段整片塗白，連「單據編號／型號」欄位標題都沒了 |
| 遮罩色會錯 | 自動取樣取到分隔線，塗成 `(238,238,238)` 而底色是純白，一塊灰斑 |
| 同一批底色不只一種 | 六張導覽列實測三種底色（scrim 疊色），單一色套整批必露餡 |
| 與紅框相交 | 要框的加號減號正好在要遮的名稱旁邊 |
| 整批一致性難維持 | 同一個單據編號，一張圖遮了、另一處明碼 |

換成假資料沒有上述任何一項——**截圖出來就是一張正常畫面**，
讀者看到完整版面，只是資料是假的。

## 只換三類

**姓名、客戶／租戶名稱、金額。**

**不換**：設備代號與名稱、單據編號、型號、品項名稱、流程說明、群組名稱、
功能代碼（畫面或選單上的程式代碼）、日期時間、數量。這些不是個資，換掉只會讓手冊失真。

> 判準是「這個值洩漏出去會傷到誰」：人名傷到個人、客戶名洩漏客戶身分、
> 金額是商業機密。設備叫「自動倉儲機」不傷任何人。

### 🔴 登入的公司一律是「示範公司」

畫面上代表**「我這家公司」**的那個名字（登入中的租戶），**固定換成「示範公司」**，
不要從假資料池抽。跨功能、跨批次、每一份手冊都一樣——讀者翻遍整套手冊，
登入的公司永遠是同一家。

**它不是客戶。** 同一張圖上常常兩種都有：

```
導覽列  <App> │ 青禾商行 │ 訂單查詢         ← 登入的公司 → 一律「示範公司」
基本資料  客戶：長興實業                        ← 客戶 → 走 ORG_POOL
```

⚠ **位置每個系統不一樣，不要寫死「導覽列那個」。** 實際出現過的位置有導覽列、
頁首、頁尾、`document.title`、列印抬頭。**靠「它代表登入的那家公司」判斷，
不要靠它長在哪裡**——換一支功能位置就變了。

工具裡是 `__anon.TENANT`（`scripts/anonymize-page.js`）。

## 流程

### 1. 載入工具（每個分頁一次）

把 `scripts/anonymize-page.js` 整個檔案內容丟進 `evaluate_script` 執行，
之後就有 `window.__anon`。

### 2. `groups()` 找出敏感資料在哪個 class

🔴 **靠位置找，不要靠文字特徵猜。**

實測：用「中文 2–4 字 ＋ 排除業務詞」去猜姓名，出現頻率前 12 名全是
「閒置」「型號」「出貨」「庫存」這類業務詞，真姓名一個都沒中。
改看 parent 的 class，`header-left header-meta-text` 底下 6 個值**全部是人名、零誤判**；
同名的 `header-right header-meta-text` 則全是狀態文字（待處理／處理中／已完成）。

**同一類資料幾乎總是共用同一個 class。** `groups()` 按 class 分群列出值，
人看一眼就知道哪一群是姓名、哪一群是金額。

### 3. `suggest(selector, 'name'|'org')` 產生對照表

⚠ **對照表要涵蓋整欄，不是只涵蓋預設頁看得到的那幾筆**——切換快篩、清空日期、打開客戶下拉，
出現的客戶都不一樣（案例：預設頁 13 家，客戶下拉 291 家，5 張標註圖帶真名到收件才被抓到）。
對整個 selector 跑 `suggest()`，每換一個畫面狀態再跑一次 `groups()` 看有沒有新值。

⚠ **對照表要保存下來重複使用**——同一個人在每張圖都必須是同一個假名，
否則讀者會以為是不同的人。金額用 `suggestMoney(selector)`（保留位數與千分位格式）。

租戶名這類單一值直接手寫進對照表，且**一律對到「示範公司」**（`{'<真實公司名>': '示範公司'}`，
見上方「登入的公司一律是示範公司」）。

### 4. `apply(map)` → 看回傳的替換次數

回傳每筆的**實際替換次數**。**某筆是 0 就是沒生效**——選錯 selector，
或該值此刻不在畫面上。0 次不要當成「沒有這筆資料」放過去。

### 5. `verify(reals)` → **必須是空陣列才可以截圖**

傳入所有真值，回傳仍然找得到的那些。非空就不要截圖。

### 6. ⚠ 每次導航或切換狀態後都要重跑 3–5 步

SPA 重新渲染會把 DOM 還原成真實資料。**換頁、開對話框、切換篩選、載入新資料之後，
畫面上又是真值了。** 每張截圖之前都要重跑一次 `apply` ＋ `verify`。

## 驗收

截圖之後，**開圖看一眼**：畫面自然嗎、假名有沒有被截斷、版面有沒有跑掉。
統計與 `verify()` 只能證明 DOM 裡沒有真值，證明不了圖好不好看
（通則見 [verify-against-source.md](verify-against-source.md)）。

## PDF 走文字層置換，不要像素改字

列印預覽／匯出的 PDF 是 JS 改不到的（那是另一份文件，不是 DOM）。**優先用 PyMuPDF
改文字層**——抽出文字物件、換值、重新寫回，字型與位置由 PDF 自己處理，
不會有字形不合或底色補丁的問題。像素改字只在文字層取不到時才用
（掃描型 PDF、文字被轉成外框）。

⚠ **MCP 驅動的 Chrome 的自動化下載不一定落地。** 觸發列印／匯出後檔案可能根本沒寫到磁碟，
**攔 blob 才拿得到 PDF**（`list_network_requests` 找那個 response，或在頁面裡把
blob URL 讀成 base64）。等下載目錄出現檔案會等到逾時。

## 什麼時候還是要用遮罩

`annotate.py` 的 `mask` op **保留為備案**，用在 JS 改不到的地方：

- canvas／SVG 圖表裡的文字
- 圖片型內容（上傳的附件縮圖、簽名檔）
- 瀏覽器 chrome（分頁標題列、網址列）——那本來就該用截圖範圍避開

這幾種情況才遮，且仍要遵守 `annotate-spec.md` 的遮罩紅線（明確指定色、開圖驗收）。

## 一個附帶好處

clean 截圖本身就不含真實個資了。它仍然留在 `.tmp/`（習慣不變），
但萬一誤 commit，傷害小得多。
