# 燈號判準

**全部比較「今天 vs 上一個工作日」，不用絕對值。**
絕對值會讓報表天天全紅——曾有版本三個 team 天天 🔴，主因是 Cycle 完成率，等於沒有訊號。

## 紅燈（今天要處理）

| 訊號 | 判準 | 寫法 |
|------|------|------|
| 驗收停擺 | 連續 N 個工作日驗收完成 0 件（N ≥ 2） | `連續第 N 個工作日，驗收完成 0 件` |
| 新增卡關 | 今天有票進入「等後端／被擋」狀態 | `今天新增 N 項卡關：{在等什麼}` |
| 新增 Urgent | 今天新建或升級為 Urgent 的票 | `今天新增 N 件 Urgent` |
| 老化跨線 | 今天有票跨過 14／30／60 工作日門檻 | `N 件今天跨過 {門檻} 天` |
| 交付停止 | 上一個工作日真實交付 0 件（扣除批次清理） | `上一個工作日零交付` |

## 黃燈（本週內要看）

| 訊號 | 判準 |
|------|------|
| 淨積壓惡化 | 新增 > 完成，且連續 3 個工作日 |
| 單段堆積 | 某一段的存量較上一個工作日增加 ≥5 件 |
| 會議吃掉時間 | 今日會議總時數 ≥4 小時（需有會議資料來源） |

## 綠燈

以上皆無 → **「今天沒有新的壞消息」**。這句話本身是有效資訊，要寫出來，
不要為了湊內容硬找問題。若當天有正向事件（解擋、交付多於平常）一併寫在綠燈列。

## 停用的判準（不得使用）

| 判準 | 為什麼停用 |
|------|-----------|
| Cycle 完成率 | Cycle 若是全票容器而非 sprint 承諾，完成率永遠偏低，無資訊量 |
| 進行中票數過載 | 「進行中 52 張」是 effort 不是 completion，屬 status theater；且含大量陳年掛單 |
| 未指派 Revisable 張數 | 絕對值，天天成立，無「今天變壞」的資訊 |
| Backlog 積壓張數 | 同上 |

## 老化門檻的前提

用門檻前必須先驗證 `updatedAt` 可信：看最後異動日分布，**單日佔比 > 30% 即為批次操作痕跡**，
該批的停滯天數只是下限。此時老化訊號整段標「本日不可用」並說明原因與影響張數。

門檻一律用**工作日**計算，不是日曆日（差約三成）。
