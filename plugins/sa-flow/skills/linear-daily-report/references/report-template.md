# 報表範本與用語規則

主報表固定四節，**零票號、60 秒讀完**。票號全部在另一份票務明細。

## 用語規則（讀者含主管，四條硬規則）

| 規則 | 反例 → 正例 |
|------|-----------|
| 功能寫白話，代碼放括號 | `{功能代碼}` → `訂單作業（{功能代碼}）` |
| 卡點寫「誰在等誰的什麼」 | `Blocked By BE 32 張` → `前端在等後端的「訂單金額統計 API」，已等 3 天` |
| 內部狀態翻成人話 | `Ready For QA` → `等驗收（測試說可以驗了）` |
| 數字附對照基準 | `32 項` → `32 項（上一個工作日 35）` |

不出現：票號、內部狀態英文名、人員票數排名、Cycle 完成率。

## 章節

### 一、今天有什麼變壞了

一句話結論＋燈號表（訊號／判準／今天）。沒有壞消息就明說，並把正向事件寫在綠燈列。

### 二、走看板（右 → 左）

**從離出貨最近的一段開始**：驗收 → 前端 → 開發 → 需求。每段固定回答三件事：

```
卡住的是什麼（件數＋與上一個工作日的差）
是什麼擋住它
誰能幫
```

需求段若含大量陳年掛單，直說「這個數字不是真的有 N 件在動」，並建議另案處理，
不要每天重複列。

### 三、今天要決定什麼

**每天最多三條，最好只有一條。** 每條含：現況／今天的具體影響／選項 A-C／
決策人＿＿／期限＿＿。

同一條連續出現要標次數：`這是第 N 次出現在報表上`。
**連續三次未認領即升級**：在該條標紅並於第一節列為紅燈。

### 附錄

- 上一個工作日完成：一行帶過（真實交付 N 件、批次清理 M 件）
- 今日行事曆：會議時數、今日不在的人、是否假日（無假日／出勤資料時註明）
- 資料警告：偵測到的批次操作痕跡與其影響

## 票務明細

固定標題 `每日票務明細 {日期}`，開頭放目錄表（清單名／件數／對應主報表哪一節）。
超大清單（等測試／等驗收／需求中）不逐筆列，改註明可在 Linear 用狀態篩選。

## 兩份都每天新建

標題帶當日日期，**不覆蓋前一天**。前一天的報表是隔天判斷「變壞了沒」的基準，
覆蓋掉就失去對照，也讓「連續第 N 次」無從計算。
