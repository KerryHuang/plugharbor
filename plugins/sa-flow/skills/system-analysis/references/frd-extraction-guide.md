# FRD 資訊提取指南（SA 用）

本指南說明如何從 FRD 系統性提取 SA 分析所需資訊。

## 總覽

| 提取項目 | 來源章節 | 用途 |
|---------|---------|------|
| 功能目標 | §1.2 | 確定分析範圍 |
| 使用者故事 | §2.1 | US-XX／角色／操作 → 工作流步驟對應與 API 設計基礎（詳下節） |
| 業務流程 | §3 | 理解業務步驟 |
| 欄位規格 | §5 | 資料模型設計 |
| 業務規則 | §5.3 | 處理邏輯設計 |
| 畫面設計 | §4 | 操作表→API、欄位語意→資訊流、選項來源→Light API（詳下節） |

## §2.1 使用者故事提取

讀 FRD §2.1 故事清單（編號｜角色｜故事｜優先級），直接沿用為分析基礎，不另建表：

- Step 4 工作流：每個工作流步驟標注 `對應 US-XX`；角色欄即泳道
- Step 8 API 建議：每個 US-XX 對應一個或多個 API endpoint（落 SAD §6.4）

## §4 畫面設計提取

對每個畫面（SCR-XX），依序提取以下三類資訊：

> FRD §4 的格式見 `${CLAUDE_PLUGIN_ROOT}/references/screen-spec-format.md`：
> 每個畫面有區塊清單、操作表、業務層有話要說的欄位、預設排序（業務語意）。
> **FRD §4 不含完整四類欄位群**（owner 為 FFS §2）——SA 階段做資訊流分析時，
> 完整欄位集合改由 `analysis/db-analysis.yml` 的表結構、`analysis/ui-survey.md` 的既有畫面現況
> 與原型取得；FRD §4 提供的是**業務語意**（為什麼必填、怎麼算、誰能看）。
> 提取時對應的欄位是「輸入語意」與「來源」，**不是**元件類型（該概念已退場）。

### A. 操作表 → API 需求

從 FRD §4 每個畫面的**操作表**（操作／觸發條件／執行後行為／權限）逐列提取：

| 操作 | 執行後行為 | 推導 API | HTTP Method |
|------|-----------|---------|------------|
| 查詢 | 依條件查詢清單 | GET /api/{resource} | GET |
| 新增（開啟表單） | 開啟新增表單 | 無 API（前端） | — |
| 新增（確認送出） | 儲存新增資料 | POST /api/{resource} | POST |
| 編輯（確認送出） | 儲存修改資料 | PUT /api/{resource}/{id} | PUT |
| 刪除 | 刪除資料 | DELETE /api/{resource}/{id} | DELETE |
| 匯出 | 產生匯出檔案 | GET /api/{resource}/export | GET |

**規則**：
- 「執行後行為」描述系統做了什麼＝至少一支 API；純畫面切換（開啟表單／關閉）不需要 API
- 確認類操作（確定、儲存）才是實際的 API 呼叫點
- 操作表的「權限」欄一併帶進 Step 8 的授權設計，勿只看操作名

### B. 畫面欄位 → 資訊流明細（IF-XX）

> 欄位來源：`analysis/db-analysis.yml`（表結構）＋ `analysis/ui-survey.md`／原型（畫面現況）
> ＋ FRD §4 業務層欄位表（語意與規則）。三者合併後逐欄對應，確保沒有欄位遺漏。

| 欄位 | 輸入語意 | 資料來源 | 寫入目標 | 對應 IF-XX |
|------|---------|---------|---------|-----------|
| （查詢條件欄位） | 文字（單行）／日期範圍／單選（可搜尋）… | 使用者輸入 | API Request 參數 | IF-0X |
| （查詢結果欄位） | 唯讀顯示 | DB 查詢結果 | 畫面呈現 | IF-0X |
| （新增表單欄位） | 依 FRD 所填輸入語意 | 使用者輸入／預設值 | DB 寫入 | IF-0X |

### C. 需選項清單的欄位 → Light API 需求

篩選**輸入語意**為下列任一者：`單選（可搜尋）`、`單選（固定清單）`、`多筆選取`、`開窗選取`。

| 欄位 | 輸入語意 | 選項來源（FRD §4 來源欄／§5 說明） | 推導 Light API 名稱 | 是否已存在 |
|------|---------|--------------------------------|------------------|---------|
| （該欄位） | （上述四者之一） | `固定清單：{值列舉}` 或 `參照{主檔名稱}` | `Get{Entity}Light` | 待確認 |

**規則**：
- 來源為 `固定清單：{值列舉}`（Enum）→ 不需要 Light API，前端靜態清單
- 來源為 `參照{主檔名稱}` → 需要 `Get{Entity}Light` API，進入 Step 7 重用分析確認是否存在
- ⚠️ 判準是**來源欄**不是輸入語意：`單選（可搜尋）` 也可能配固定清單，
  `單選（固定清單）` 若配 `參照{主檔}` 則屬 FRD 填寫錯誤，回頭確認而非直接推導
