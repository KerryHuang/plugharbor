# 環境安全 — 判定與唯讀降級

## 1. 環境判定(由 URL)

| 判定 | 規則 | 允許 |
|------|------|------|
| 開發/測試 | host 含 `localhost` / `127.0.0.1` / `-test` / `-staging` / `.local` | **完整操作**(含寫入) |
| 正式 | host 含 `-prod` / 正式客戶網域 / 無上述測試標記的對外網域 | **唯讀** |
| 判不準 | 無法明確歸類 | **唯讀(保守預設)** |

> 規則之外的客戶自架網域**一律當正式**處理,先問使用者確認才升級權限。

## 2. 唯讀降級

唯讀模式下:
- **允許**:`new_page` / `navigate_page` / `take_snapshot` / `take_screenshot` / `list_console_messages` / `list_network_requests`。
- **禁止**:`fill` / `click`(會觸發變更的)/ `drag` / `upload_file` / 任何送出表單的動作。
- 需要在正式環境做變更時:`AskUserQuestion` 取得使用者**該次顯式授權**,並只放行被授權的最小動作。

> 純導覽性的 `click`(展開選單、切分頁)與變更性 `click`(送出、刪除)難以自動區分時,**從嚴**:在正式環境先確認再點。

## 3. 破壞性操作確認

即使在 test/staging,以下動作執行前一律 `AskUserQuestion` 確認:
- 刪除 / 作廢 / 取消。
- 批次操作。
- 不可逆送出(過帳、結案、拋轉)。
- 會改動他人正在用之共享資料的動作。

## 4. 稽核

- 變更性操作前在對話中**明說「將執行 X」**,讓使用者可中止。
- 產出報告記錄實際操作的環境 URL 與是否動到資料,便於追溯。
