# FFS 撰寫派工樣板

`specify-frontend` Step 5.4 的 `spec-writer` 派工 prompt。
派工**前**必須先完成 5.1 契約回查、5.2 邊界落實對照、5.3 決策落檔——
agent 拿到的 BFS 必須已是回查修正後的版本，`decisions.md` 也要已 append 完成。

`{}` 為呼叫端填入值；所有路徑一律展開成**絕對路徑**。

```
subagent_type: "sa-flow:spec-writer"
prompt: |
  doc_type: FFS
  out_path: {功能目錄}/{功能名稱}_前端功能規格書.md
  template: ${CLAUDE_PLUGIN_ROOT}/templates/ffs.md
  boundary_row: {spec-dedup-and-budget.md「各文件套用值」表的 **FFS 欄**（表頭是 `項目｜FRD｜SAD｜BFS｜FFS`，要抽的是那一**欄**跨全部項目列）}
  evidence:
    - {FRD 路徑}          # §4 畫面清單與操作表
    - {BFS 路徑}          # §6 端點契約（5.1 已回查修正過）
    - {SAD 路徑}          # §6.6 邊界清單
    - {功能目錄}/analysis/ui-survey.md    # §2 完整欄位表的主要取材來源
  decisions: {功能目錄}/decisions.md ＋ 本階段編號 {D-0xx, D-0yy}
  feature: {功能名稱}／{模組}／{功能目錄}
  brief: |
    §2 四類欄位群**沿用範本語彙**（查詢條件／查詢結果／新增表單／編輯表單差異），
      **不要另立「顯示欄位／輸入欄位／前端計算」這套**——兩套分法會讓 agent 得自己對應。
      逐頁列各類的取材落點，以及 5.1 契約回查的對照結論
    §2 區塊清單與欄位順序：依建檔決策順序分區
      （不照資料表欄位家族），親緣欄位與同性質量值相鄰；
      **§5.0／§5.1 每對觸發→影響欄位的「所屬區塊」必須相同**——跨區的連動在使用者眼中就是資料被偷改
    §5 自動帶值寫明連動強度：使用者改過的欄位是否仍會被覆寫
    §3 只寫功能特有流程與偏離標準 CRUD 之處；無則一句帶過
    §4 一律 ref BFS §7 同編號 VR，不重寫字面值
    §5 有計算或判定邏輯時附一組「輸入→輸出」具體例：
      數值計算給數字；**布林／狀態判定給條件組合→畫面結果**（不要假設一定是算術）
      已在 FRD §5.3 有業務算例者 ref 之，此處只補前端精度差異
    §6 端點對應表引用 BFS，不重複定義
    §7 舊系統對應：**{呼叫端已判定的結果}** ——
      「需填實，舊系統為 {X}」或「N/A — 無舊系統對應，判定依據：{一句}」。
      **不要讓 agent 自己去掃 CHANGELOG 判定**，那是呼叫端的判斷
    §8 每個 TC 標注對應的 FRD US-XX
    5.2 邊界落實對照結論：{B1/B2/B3→§4、B4/B7→§5、B11→§2 的逐項落點}
    內容規範必讀：${CLAUDE_PLUGIN_ROOT}/references/screen-spec-format.md（畫面內容規格格式）
                 ${CLAUDE_PLUGIN_ROOT}/references/sort-order-standards.md（排序五要素）
  mode: new
  extra_checks: |
    EC-1｜§2 四類欄位群在功能層級齊備（不適用者寫「無」或註明由其他畫面承載）；
        無省略號；每個顯示欄位來源填 BFS §6 Response 欄位名或 `前端計算：{公式}`，
        不得留空／占位符／ref 帶過｜逐頁逐欄看「來源」欄有無空白
    EC-2｜全文無框線字元、無元件名稱、無像素寬度｜grep -nE '┌|─|│|└|├|┼|px|{前端框架／元件庫名稱，依專案技術棧列舉}'
```

<law>
**EC-1／EC-2 是硬閘，不通過不得產出。** 畫面內容規格**沒有視覺下限**——
只填佔位符的表格看起來是滿的，交付物卻更空。§2 是全鏈唯一完整欄位表、**沒有上游可 ref**，
這閘沒過，Dev 前端票就沒東西可取材。
</law>


## 編號前綴為什麼用 `EC-` 而不是 `L`

`spec-dedup-and-budget.md` 的「Lint 補項」欄（BFS／FFS 兩欄）已定義
**L9 SPEC-INDEX、L10 正文預算、L11 必畫圖、L12 算例**；
四支規格 skill 的自檢又另外用 L14 必畫圖、L15 算例、L16 §0。

`extra_checks` 若也叫 L11／L12，agent 回報「L11 未過」時**無從判斷指的是欄位群還是必畫圖**。

> 實測：agent 明確回報這是「最該修的一條」——
> 它自檢時得同時滿足兩套定義，並自己決定回報時 L11 指哪一個。

**新增 `extra_checks` 一律用 `EC-` 前綴**，不要沿用 `L` 系列。
`spec-dedup` 與 skill 自檢之間的 L 編號不一致是既有問題，另案處理，但別再加劇。

## 派工 prompt **不必**寫的東西

以下已在 `spec-writer` 定義裡，重述不會帶來新資訊，只會稀釋 prompt 的訊號：

- 「不做決策／不重新蒐證／不與使用者互動」三條
- 「定向讀取、不整檔載入」的讀取紀律
- 正文預算的量測指令、SPEC-INDEX 的核對方式

> 實測：agent 自己點名這幾條多餘。

**該寫的是它定義裡沒有、只有呼叫端知道的**：實查過的章號、判定結果、
既有編號體系與**已被外部引用的編號區間**、本功能的結構限制、證據檔的實際路徑。

### 一條看似多餘、實際救了一手的

`EC-2` 的框線字元 grep。驗證時 agent 回報：FRD §4.2 有兩張框線 ASCII 示意圖，
**沒有這條提醒的話，把「畫面示意」搬進 §2 是很自然的動作**。

判準：**如果上游 evidence 裡存在「看起來該抄、實際不該抄」的東西，就值得寫一條硬閘**——
那不是重述定義，是針對本次素材的具體防呆。
