# SPEC-INDEX 與體積檢查細則

> 對應 Task 8.8「文件邊界去重」表中的兩個 WARNING 項目。

## SPEC-INDEX 檢查（依索引形狀分流）

先讀 `<!-- SPEC-INDEX v1 -->` 標記後緊接的第一個 `>` 行，判斷形狀：

- `> **章節索引**`（一般規格文件 FRD／SAD／BFS／FFS）→ **完整格式**。
  檢查：索引逐行列出的 `§X` 章節與文件實際 `^## ` 章節**一一對應**（無多無少）；
  有編號序列的章（US／BR／VR／IF／TC）標示的編號區間與正文實際出現的編號一致；舊版文件出現的 UC-XX 視為 legacy 合法編號，不判缺漏。
- `> **異動摘要**`（CR-FRD／CR-BFS／CR-FFS）→ **CR 簡化格式**。
  檢查改為**子集比對**：異動摘要提到的 `§{章節清單}` 必須都存在於文件的 `^## ` 清單中；
  文件章節不必全部出現在摘要（CR 文件本身章節數固定，不逐項列舉）。CVR／CBR 編號區間比照上述一致性檢查。
- 兩種形狀不可共存於同一份文件；若同時出現兩種開頭視為格式錯誤，記一筆 WARNING。
- 完全缺 `<!-- SPEC-INDEX v1 -->` 標記 → WARNING，並在報告中提示「該文件缺 SPEC-INDEX，建議補」。

## 體積檢查（正文預算）

量的是**正文**：從第一個 `## 1.` 起到 `## D.` 之前，**不含** §0 一頁摘要、§D、附錄、CHANGELOG。

```bash
F={規格檔}
awk '/^## 1\./{p=1} /^## D\./{p=0} p' "$F" | wc -c
```

上限：FRD／SAD／FFS ≤30KB、BFS ≤45KB（定義權威在 `${CLAUDE_PLUGIN_ROOT}/references/spec-dedup-and-budget.md`）。
判準優先序：

1. 該用 ref 的地方有沒有 ref（8.8 表格前三項 BLOCKER 已覆蓋，此處不重判）。
2. 示範用的 JSON／範例是否已抽到 `templates/examples/`，正文只留欄位表（依
   `${CLAUDE_PLUGIN_ROOT}/references/doc-boundaries.md`「BFS §6 表達法」）。
3. 以上都做到仍超標 → **拆附錄檔**，不放行。

超標時，報告**不要**只寫「請壓縮」，要具體指出：

- 哪幾章最肥（用章節位元組數估算，列前 2~3 章）；
- 其中哪一章適合整章搬成 `{功能名稱}_附錄_{主題}.md`（典型：API 契約明細、欄位對照全表、
  測試案例全表），主文只留總覽表＋連結，SPEC-INDEX 該章一行註明「明細見附錄檔」；
- 該功能目錄下是否有已 Done 的 CR 文件，其異動已可併回主文件；
- 若肥的章節是 JSON 範例而非欄位表，優先建議改走 §6 表達法。

「確認放行」不再是選項；文件仍超標而未拆，須在 `decisions.md` 有一列「體積放行」及理由，
否則列 WARNING。
