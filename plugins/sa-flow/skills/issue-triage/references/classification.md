# 分類準則與防呆（issue-triage §3）

## 分類定義

| 類別 | 定義 | 判準 |
|------|------|------|
| **Bug** | 現行功能異常 | 「本該動卻不動」；勘察為已實作但壞掉 |
| **Enhancement** | 調整／擴充既有功能 | 改欄位／預設值／版面／查詢條件／既有行為 |
| **Feature** | 全新能力 | 勘察為未實作、且無既有規格鏈 |

## 防呆（開票前必過）

1. **「客戶說缺少」≠ 真的沒有**：最常因 **版本差異**（標準版 vs lite）、**capability flag 未開**（整個功能欄被 flag 藏住）、**測試點／入口沒找到**。勘察若顯示已實作 → **不歸 Feature**，改標「先實機確認、勿逕自開發」，放入「已實作防呆」區。
   > 實例：複製訂單／分頁／autocomplete／常用項目／狀態燈號，客戶都說「缺少」，實際已實作。
2. **既有票／規格鏈對照**：標「需新建」前查 **docs＋Linear**；多數主題已有鏈，以 **CR 併入既有票**，勿另開重複票。
3. **變體／術語先確認**：客戶／場域變體、版本命名對照先定，分類才不會建立在錯前提上。
4. **純現況描述非需求**：客戶只是「說明行為／定義」的，不列為問題（標註即可，勿當需求開票）。
5. **證據＋信心度**：每項分類附勘察證據（file:line／文件路徑／票號）與信心度——**Confirmed**（有證據）／**Likely**（合理推論）／**待實機**（需開畫面／查租戶設定）。
