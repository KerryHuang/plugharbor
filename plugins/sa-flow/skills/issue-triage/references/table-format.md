# 分類問題清單格式（issue-triage §5–6）

## 檔案結構（順序）

1. **抬頭**：來源、對照範圍（後端／前端／docs）、分類定義、信心度說明、**變體／術語提醒**。
2. **統計摘要**表（各類數量）。
3. **§1 已實作防呆表**：現況已實作、客戶卻反映「缺少」者 → 先實機確認、勿逕自開發。
4. **Bug／Enhancement／Feature 三分類表**。
5. **待釐清表**（含 PO 定案欄）。
6. **既有票／規格鏈對照表**（避免誤判需新建）。
7. **建議下一步**。

## 各分類表欄位

`# | 模組 | 項目 | 現況勘察 | 既有票/規格鏈 | 優先 | 已完成`

- **同模組相鄰**：列依模組歸群排序，同模組放一起。
- **ID 連續**：每類獨立連號（`BUG-01…`／`ENH-01…`／`FEAT-01…`）。
- **優先**：高／中／低（先給建議值，PO 可調）。
- **已完成**：`✅` 或狀態（需 QA／需修改／已有票 ENG-xxx…）。

## PO 裁決與維護

- 逐項與 PO 確認分類／優先／狀態。
- **PO 直接改檔時**：以**當前檔為準**再改；**只補自己被蓋掉的改動、保留 PO 所有註記**，勿覆蓋。
- **ID 重編（連續化）時**：依模組順序重排列後，**同步更新所有交叉引用**（§1、待釐清、跨表「見 XXX」）；被移除項的歷史引用**改用項目名**（勿用舊 ID，避免與重編後的新 ID 撞號）。
