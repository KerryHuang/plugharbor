# 三路 grounding 派發（issue-triage §2）

分類前先對照現況 codebase，避免憑會議字面分類。

## 1. 先問路徑（不寫死）

以 `AskUserQuestion` 取得後端、前端、docs（規格鏈）各自路徑。可從專案 CLAUDE.md 或目錄結構推導預設值當選項。

## 2. 並行派 3 個 Explore（單一訊息內）

把「依模組拆好的 item 清單」交給三路，各問其領域現況：

- **後端**（如 `apps/api`）：每項在後端「已實作／部分／未實作／疑似壞掉」＋ file:line 證據。聚焦資料／邏輯面——欄位是否存在、預設帶入邏輯、卡控／守衛、狀態機、查詢維度、聚合值。
- **前端**（如 `apps/web`）：每項在畫面／互動面的現況＋元件證據。**特別注意版本差異**（如標準版 vs lite；同功能不同版可能落差）。
- **docs 規格鏈**：每主題**是否已有 FRD/SAD/BFS/FFS/CR 或票號**，回報文件路徑與票號，避免誤判「需新建」。

要求各 Explore：逐項輸出「item → 現況 + 證據」；medium 廣度；不確定標未知，勿臆造。

## 3. 收斂

主 session 收三份，交叉比對：
- 後端有、前端無（或反之）＝**部分**。
- docs 有鏈＝標**既有票**（供分類時對照，避免重開）。
- 多處同症狀（如多畫面「看不到圖片」）＝疑同一根因，標「合併調查」。
