# Operation Manual — 操作手冊與簡報產出

> 非 Claude Code（如 Pi）執行時，先讀 `../../references/harness-terms.md`（相對本檔；Claude Code 為 `${CLAUDE_PLUGIN_ROOT}/references/harness-terms.md`，照字面執行可略過），把 Claude 專屬工具與路徑換成對應項。

把一支已上線的功能，做成**交給使用者／客戶的**操作手冊（PDF）與教育訓練簡報（PPTX）。

> **分工**：`live-drive` 是通用實機操作（重現 bug、跑 e2e），本 skill 是手冊特化流程、**共用登入設定**；
> 手冊流程與 `qa-verify`（驗收報告）產物、落點都不同，**兩者互不取代**。

## 產出

**交付物從一開始就直接寫在最終位置，不經搬移。**

```
{docs-root}/操作手冊/{模組}/{功能}/   ← 交付物，納版控（模組目錄取自 docs 既有第一階目錄，不自創，新增先問使用者）
  {功能名稱}_操作手冊.md ／ {功能名稱}_操作手冊簡報.md（Marp）
  images/aNN-<英文語意名>.png         只有 annotated 版
.tmp/operation-manual/{功能}/         ← 中間產物，不納版控
  inventory.yml  gaps.yml  spec-db-evidence.md  annotation_requests.yml  friction.md
  sNN-*.png                           clean 截圖（假資料已在截圖前換好，仍不進 docs）
```

分界是**交付物 vs 中間產物**，不是「審查前 vs 審查後」。搬移本身就是出錯來源，能不搬就不搬；
clean 截圖一律留 `.tmp/`。真正的關卡是 **git**——檔案在工作區不等於進版控。**md 是終點**，PDF／PPTX 是衍生物、不進版控。

## 權威來源

專案的操作手冊範本——`操作手冊撰寫範本.md`（體例與撰寫規範）、`_骨架_操作手冊.md`、`_骨架_簡報.md`，
慣例放在 `{docs-root}/操作手冊/_範本/`（或專案 CLAUDE.md 指定處）；參考實作是專案內一份已交付的手冊。
**找不到範本就問使用者**（提供位置，或確認以 `manual-writer` 的預設體例為準），不自創體例。
登入設定在 `.claude/live-drive.local.md`（本機檔，未納版控）。

**寫作前一定要讀範本規範**——體例、圖文比、用語標記、不放內部資訊都在那裡，
本 skill 不重複載明，避免兩處漂移。

> **主 session 不產文件。** 手冊、簡報、證據彙整、審查報告、分流清單全部派 agent 寫，
> skill 只負責派工、判讀回報、機械性落檔與裁決。
> **規範的建議 ≠ 替使用者決定的授權**——「優先用 X」「建議 Y」是取捨參考，
> 起手參數（環境、目標、模式）與處置方式**一律問使用者**。

## Laws

<law>
**環境限制**：只在 `-test` / `-staging` / `localhost` 操作。命中 production 或判不準 →
中止，不得以唯讀模式勉強進行（手冊要完整走過新增流程，唯讀拍不到關鍵畫面）。
</law>

<law>
**建立測試資料要可辨識**：允許在測試站建資料，但品名與備註**必須**帶
「操作手冊示範用」字樣。⚠ 許多單據沒有刪除功能（如訂單），建了清不掉——
建之前先確認能不能刪，且**軟刪不等於清乾淨**，收尾要回報有無軟刪殘留列。

**交付物不得含內部資訊與個資**：規格路徑、票號、資料表名與欄位、盤點編號、「待補」進度一律
不進手冊。截圖上的**姓名、客戶／租戶名稱、金額**三類**在截圖前換成假資料**、不事後遮罩（見 S2a），
其中**登入的公司一律用「示範公司」**（認語意不認位置）。**S6 未通過不得 commit**——工作區只是草稿。

⚠ **功能代碼（畫面上標示的程式代碼）不是內部資訊，不要遮**——它對使用者報修有用、封面就要填，正文也用它指引讀者辨識功能，
**截圖上的代碼標記一併保留**；不准出現的是 `orders.order_no` 這種資料表欄位。（誤遮代碼會與封面、正文自相矛盾，整批圖重做。）

**誰寫哪裡**：`manual-writer` 只寫派工指定的那一個路徑（未指定時回傳全文由 skill 落檔）；
`manual-explorer` 的 annotated 圖直接寫進 docs 的 `images/`，clean 截圖與其餘中間產物
一律寫 `.tmp/`。**clean 截圖永不進 docs。**
</law>

## 流程——預設平行，只有真有資料依賴才串接

```
S1 準備（skill）
  ├─ S2a 實機探索 ·· manual-explorer ·┐ 瀏覽器
  └─ S2b 規格與 DB · scout ···········┤ 唯讀 DB 工具（如有）＋ 讀檔
S3 撰寫 ·········· manual-writer ···· 手冊 md 草稿 ＋ annotation_requests
  ├─ S4 截圖標註 ·· manual-explorer ·┐
  └─ S5 簡報撰寫 ·· manual-writer ····┤
S6 審查 ·········· manual-reviewer ·· 七項檢查，**未過不得 commit**
S7 交棒（skill）·· gaps.yml → **依類型分流**，不是一律開票
S8 產交付檔（skill）**必問格式**，問完才產；不問就是漏做
```

S2a ∥ S2b 用不同工具寫不同檔案；S4 ∥ S5 一個產圖一個寫字，
**檔名在 S3 的 `annotation_requests` 就約定好**，簡報不必等圖到位。
**真正的依賴只有兩處**：S3 要等兩份證據到齊、S6 要等手冊與簡報都定版。
派平行 agent 時務必明講「另一個 agent 正在寫 X，不要碰」。

### 時間預算

盯**退件次數與根源在哪一棒**，不是總時長。**S6 退回＝上游漏了東西在下游補。**
**卡點當下記，不留到收工回想**：退件、重派、重拍、被糾正、agent 卡住，發生當下就在
`friction.md` 記一行「棒｜發生什麼｜根源在哪一棒｜代價」，每份派工回報末尾附「卡點」（無則寫「無」）。
收工時 run-log 由此整理，空檔記「clean run」，**「S1→S6 通過」填分鐘數**（跨日填累計工時估算），
S4 拒產張數寫備註——不記就看不出趨勢。歷次紀錄與好模式見 [references/run-log.md](references/run-log.md)。

### S1 準備

0. **工具就緒檢查**：跑 `${CLAUDE_PLUGIN_ROOT}/scripts/ensure-tools.sh`
   （檢查並協助安裝 Chrome／node／pandoc／python+markdown；`--check` 只檢查）。
   **換一台機器第一次用一定要跑**——別台電腦不會預裝，探索到一半才發現缺工具要重來。
1. 確認**功能與模式**：同一支功能有多種模式時（標準版／複合版）一次只做一種，
   模式靠目錄區分，手冊內文不出現另一種模式。
2. 讀既有規格（FRD／FFS，位置依專案 `{docs-root}` 結構）建立預期行為供 S6 比對；沒有規格就從前端實作與畫面整理，並在 inventory 註明「無規格」。
3. 列出要走的畫面與路由清單，交給 explorer。
3b. **同時列一份「規格分支清單」，這是必做的一項，不是加分項。**
   路由清單回答「有幾個頁面」，分支清單回答「同一個頁面有幾種樣子」，**兩者不能互相替代**。
   從 FRD／FFS 抽出每一個**條件分支**（提示各分支、空狀態各種、權限差異、上限極值、狀態機訊息）交給 explorer，
   **逐條標三態**（已驗證為真／已驗證為不存在／未驗證＋原因），**不准留白**——留白會被下游讀成「不存在」。
   S2b 證據檔若點名「某分支容易造得出來」，那條就是必測。三態定義與事故見
   [references/exploration-checklist.md](references/exploration-checklist.md)。
4. **環境一定要問使用者，不可自行決定。** 讀 `.claude/live-drive.local.md` 列出可選環境並講清取捨——
   內部 demo（資料乾淨省去換假資料，但不一定有該功能、樣態不真實）vs 客戶副本測試站（畫面即客戶所見，但整頁真實個資）。
   選定後才取登入資訊。**規範寫「優先內部 demo」是個資政策建議，不是決定環境的授權**——不要據此自己挑。

### S2a 實機探索（`manual-explorer`，mode=explore）

先跑 `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/browser-doctor.py`，非 `OK` 就停，照它印的標準寫法請使用者改註冊後重啟 session。

> **瀏覽器工具**：agent 固定 `chrome-devtools`（`--isolated`）；`claude-in-chrome` 只給主 session
> 人機互動，見 `${CLAUDE_PLUGIN_ROOT}/references/browser-tooling.md`。截圖要**指定檔名**、**fullPage**、精確視窗尺寸。

輸入：URL、登入資訊、路由清單、**分支清單**、功能名稱、`isolated_context: manual-<功能碼>-<分組>`
輸出：`.tmp/operation-manual/{功能}/inventory.yml`、`screenshots/`（clean）、`gaps.yml`

inventory 必須帶回兩塊給下游用：

- **`分支銷帳`**：分支清單逐條的三態結果（S6 會拿它查窮舉斷言）
- **`可標註元素`**：`sel`、`rect`、`於: <截圖檔名>`。`於:` 是這筆 rect 的**有效條件**——同一 route
  各狀態位置完全不同，各記一組；「已確認」不等於量對，套用前仍要驗映射。
  🔴 **這是關卡不是建議**：一個畫面「截圖 → 立刻量完 → 寫回 inventory」才准走下一個，不准事後補量，
  **測試資料一刪就回不去**；toast 這類會消失的尤其要記，**且要確認它真的在圖裡**。
  🔴 **收件先跑 `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/check-inventory-rects.py <inventory*.yml> --shots <clean 截圖>`**，非零就退回該組補量、**不進 S3**
  （零 rect 的截圖、「約」、超出圖面；純全景不框的截圖除外）。只數銷帳三態就放行會漏檢。

探索檢查表（三態定義、必記項目、常漏清單、事故細節）見 [references/exploration-checklist.md](references/exploration-checklist.md)。
🔴 **客戶環境一律在截圖前用 JS 把敏感值換成假資料，不要事後遮罩**——遮罩會連版面一起蓋掉。
**只換姓名、客戶／租戶名稱、金額**；設備代號與名稱、單據編號、品項、流程說明**不換**，換掉手冊就失真。
工具、四步驟與事故見 [anonymize-before-capture.md](../../references/anonymize-before-capture.md)。
inventory 範例值一律寫佔位符（`<員工姓名>`）——中間產物會被後續每一棒讀進 context。

### S2b 規格與 DB 蒐證（`sa-flow:scout`，與 S2a 同時派）

補**畫面看不出來**的那一半：欄位型別與**長度**（手冊要寫「姓名最多幾個字」）、
必填 NOT NULL（與畫面紅星號比對，**不一致就是一條 gap**）、預設值與值域、軟刪除欄位、
規格 BR／VR 清單、系統內建說明（in-app help，若有；描述常比規格新）。

輸出 `.tmp/operation-manual/{功能}/spec-db-evidence.md`。有了 DB 這一份，
**gaps 才能做三方比對**（規格說 vs 畫面顯示 vs DB 實際結構）——
沒有 DB 工具或只有畫面證據時，手冊寫不出任何欄位限制。

### S3 撰寫（`manual-writer`）

輸入 inventory.yml、`spec-db-evidence.md`、截圖清單、範本規範與骨架路徑；輸出手冊 md 全文
＋ `annotation_requests`。skill 收到後**直接寫進交付目錄**，不先寫 `.tmp` 再搬。

### S4 標註（`manual-explorer`，mode=annotate）——**依畫面狀態分組平行**

依 `annotation_requests` 加紅框與標籤。explorer **直接把 `aNN-*.png` 寫進交付目錄的
`images/`**，clean 版 `sNN-*` 留在 `.tmp/` 不動。

#### 這一棒不做量測，也不回 live 重拍

**預設在 clean PNG 上用 PIL 疊**（`${CLAUDE_PLUGIN_ROOT}/scripts/annotate.py`，
spec 見 `${CLAUDE_PLUGIN_ROOT}/references/annotate-spec.md`）。座標來自 inventory 的
`可標註元素` 或 live DOM，**不從 PNG 目測、不用等距推算**；派工時把該組要用到的
`rect` 一併貼進去。只有兩種情況要回 live——inventory 沒記到那個元素，
或記到的 `於:` 不是要的那張圖，取完**補記回 inventory**。

**這一棒通常不必遮罩**（敏感值已在 S2a 換掉），遮罩只剩 JS 改不到的地方（canvas／SVG、圖片型內容）。
真要遮：🔴 **畫進像素不能用 CSS 疊**（`#3467A9` 截出來是 `(65,102,164)`）、**跨元件明確指定色**、
**開圖驗收**、**先算與紅框有無相交**。

#### 依畫面狀態分組——不要照抄別支功能的分組表

逐張列出前置條件 → 前置路徑相近的歸一組 → **需要寫資料的單獨成組** → 一組一個 agent 各開自己
的分頁。**判準是「起始狀態」**：跨組要重新導航、或要改變資料才能到位就切開；一組少於兩張不值得切。

#### 派工訊息一定要帶的七件事

缺一項就重踩舊坑：①各自開分頁、**每次工具呼叫都帶自己的 `pageId`／`tabId`**（否則「當前選中頁」被別組切走）
②開頁後先 `emulate 1680x1000x2`（`resize_page` 已移除），per-page 才不互相干擾
③只處理指定檔名，**輸出檔名已分配**（否則覆寫別組產出）
④指定**專用工作目錄**（`scratchpad/g1/`…）與 `isolated_context: manual-<功能碼>-<分組>`（否則中間檔撞名、隔離環境互相污染）
⑤**派工前先讀 agent 定義的 `tools:`**，只派清單內做得到的事，開場請 agent 回報「我有哪些工具」（照 MCP 全表派工會派到 agent 沒有的工具，如 `upload_file` 只有主 session 有，自報才發現得了）
⑥**收尾只關自己的分頁**（主 session 若手動起過 Chrome，測完必關並驗證）
⑦**帶上上游的環境前提**（測試資料可建次數等限制不會自動繼承到下一棒）

**每條約束都寫成三段：約束｜為什麼｜何時解除。** 只寫約束，前提過期後沒人敢撤（第 2 條即實例）；
執行棒遇到約束擋住正事時**停下來問呼叫端**，不自行解除也不死守。第 7 條指的是 S2a 派工寫過、
S4 不會自動繼承的東西：測試資料命名與**可建次數**、不可重複的操作、該環境既有限制——**約束不會自己走到下一棒。**

⚠ **會寫資料的組不要跟其他組同時動**——它會改變清單筆數。

#### 收件時對帳 caption——這一步不能留到 S6

caption 是 S3 在標註動手**之前**寫的（「紅框處為 X、Y、Z」），標註棒常有正當理由
少框一個，**而那句話不會自己跟著改**。對不上就當場改 caption 或要求補框，
**不要送進 S6 等它退**（曾致重拍加重審 33 分）。

🔴 **對帳要開圖看紅框裡實際是什麼，不是拿 caption 比對「實際標註清單」**——那兩份都是文字，
**雙方同時說錯會互相印證成「一致」**。清單拿來**定位該看哪幾張**，結論回到圖上。通則見
[verify-against-source.md](../../references/verify-against-source.md)。

🔴 **標籤底下原本必須是空白**，只驗「不壓紅框」不夠；擁擠的圖（相鄰多框、貼近清單或工具列）由**呼叫端先開圖指定標籤座標**。**手冊圖不用 legend**——會把圖加高，整批尺寸不一。
> 分組推導、七件事出處、遮罩相交、caption 缺口、標籤位置事故——見 [references/annotation-dispatch.md](references/annotation-dispatch.md)。

### 中途加派：跟 S3 平行，不要排在它後面

證據不足要補查時（對帳、追異常、隔離變因），這些棒**不碰瀏覽器也不寫手冊**，和 S3 零依賴——
**跟 S3 同時派**，不要等它交稿再排隊。補測類要交代**一次只改一個條件**：呼叫端給的步驟
未必做到變因隔離，agent 有義務先看那組步驟會不會讓兩個條件同時成立（好例見 run-log）。

### S5 簡報（`manual-writer`）

依**定版後的手冊**產 Marp 簡報，不另外從 inventory 重寫，避免兩份內容漂移。
收件後 skill 用 `build-deck.sh` 產到 `.tmp/`（自動跑溢出檢查）——**說明框被擠出投影片只有 PDF 看得到**；有溢出就退回 S5（截圖不得小於 `h:380`，放不下拆「（續）」頁）。

### S6 審查（`manual-reviewer`）

七項檢查，任一不過退回 S3——① 圖文比（跑
`${CLAUDE_PLUGIN_ROOT}/scripts/text-image-ratio.py`，200～400 通過、>600 不過）
② 內部資訊（規格路徑／票號／資料表欄位／「待補」皆不存在；**程式代碼允許**）
③ 個資與客戶資料逐張確認
④ 圖片完整性（都存在、無孤兒圖、只用 annotated 版、**開圖看紅框再對 caption**）
⑤ 內容一致性 ⑤b **窮舉斷言**（「三種／只有／全部」要對得上 `分支銷帳` 全數已驗證；
**「顏色→狀態」這類屬性綁語意同樣是斷言**）⑥ 模式純度
⑦ **整批一致性與交付適配**——逐項合規不等於整體能用：同一個值在整批圖處理方式一致嗎
（一處遮一處沒遮＝第 3 項紅線）、每張圖適不適合交給客戶看（底圖拍髒了要重拍）、**簡報 PDF 無溢出**（reviewer 自產到 `.tmp/` 跑檢查，溢出＝必須修正）。

逐項判準在 `manual-reviewer` 裡。**reviewer 不採信任何自報數字，包括呼叫端的。**

**第 1 項一律跑腳本**——舊算式 `len(整份檔案)/圖片數` 分子含圖片語法，**每補一張圖分子就變大**。
第 5b 項在查**三方共同的沉默**：規格、畫面、DB 都沒提的東西比對不出不一致，所以要反查每個封閉式斷言的分支是否全部驗過。

**七項全過就 commit**——交付物已在 `{docs-root}` 裡，之後的校正與 diff 都在 md 上做。

### S7 交棒——gaps 依類型分流

`gaps.yml` 是本 skill 的**副產品，也是它對 SA 的主要價值**，但**不要一律開票**——
先逐條判類型：能自己收掉的當場收掉，只有真的需要人決定的才留下來問。

| 類型 | 判準 | 處置 |
|---|---|---|
| **規格文件寫錯／過期** | 實作是對的，文件沒跟上 | ⚡ **當場派 agent 直接改** |
| **schema 記載與實際不符** | 文件記的型別長度跟 DB 實際不同 | ⚡ **當場改**（僅限文件，見下方紅線） |
| **實作有錯** | 標必填卻不驗證、算錯、存不進去 | ⚡ **當場開票** `sa-flow:linear-create` |
| **已被推翻／純現況記錄** | 複驗後不成立，或只是把現況寫下來 | ⚡ 丟掉，不要留 |
| 規格與實作都合理但不一致 | 兩邊各有道理 | 🙋 **留下來逐題問** |
| 規格未定案 | 規格自己就標「待確認」 | 🙋 **留下來逐題問** |
| 資料品質 | 客戶存量資料有問題，非系統缺陷 | 🙋 **留下來逐題問** |
| 判不出來 | — | 🙋 **留下來逐題問**，不要硬歸類 |

**⚡ 那四類不進清單**——證據此刻最新、人還在場，進了清單就是等它爛掉。回寫規格類
**不需要任何人決策**（實作是權威，文件錯了就是事實訂正），派 agent 直接改並在該文件檔頭
CHANGELOG 補一列「完工回寫：實作對齊」，可與 S8 平行。🙋 那四類用 `AskUserQuestion`
逐題問，一次問完；**判不出來就問，不要硬歸類**——開錯票會佔用 Dev 的時間。

🔴 **文件可以直接改，DB 不行**：schema 類只准改文件，加寬欄位是 DDL，依專案的 schema 治理規範（如有）
要 PO 授權、**一律唯讀查證後回報**；「驗證上限與欄位
長度不符」是行為變更不是訂正。**三個要擋下來、退回 PO／PM 的情況**（派工時明講）：
改規格等於要求實作改行為／觀察來自單一客戶的變體／該事實只在一種資料樣態下成立。

> 執行細節、為什麼清單會爛掉、分類實例——
> 見 [references/gaps-triage.md](references/gaps-triage.md)。

**瀏覽器收尾**：agent 只關自己的分頁；主 session 若為本次手動起過任何 Chrome（含 9222 附掛），在回報完成的同一輪關掉並驗證（`curl -s -m 2 http://127.0.0.1:9222/json/version` 無回應、無 `puppeteer_dev_chrome_profile`／`claude-shared-chrome` 行程）。

### S8 產交付檔——**必問格式**

md 是終點，交付檔是衍生物。**要不要產、產哪種，一律問使用者**——這**不是選用步驟，是流程的最後一棒**
（曾因放在流程外當附註而被跳過）。用 `AskUserQuestion` 問，選項固定四個：**標準 PDF**（預設建議，
手冊＋簡報 PDF）／Office 系列（Word＋PowerPoint）／兩者都要／先不產。

**產出一律落 `.tmp/`，不進版控**——`build-deck.sh` 的輸出目錄是必填參數，指到 `.tmp/` 下；
產完再確認一次版控目錄沒有 PDF／PPTX，**簡報溢出檢查沒過不交付**。指令、`.python-path` 的取法，
以及兩個要**先告知使用者**的限制（PPTX 每頁是圖片、文字不可編輯；Word 的分頁與封面仍與 PDF 有差）
——見 [references/build-deliverables.md](references/build-deliverables.md)。

## 局部更新（`--update <section-id>`）

手冊每章有 `<!-- section: <id> route:<route> -->` 標記。只重寫某一章：讀該 section 的 route →
explorer 只走該畫面 → writer 只寫該段 → 拼回原檔 → S6 只驗該段與全域的內部資訊／個資。
