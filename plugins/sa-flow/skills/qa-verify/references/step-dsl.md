# 步驟 DSL（Domain Specific Language）

步驟 DSL 是為本 skill 設計的結構化執行語言。詞彙表與執行語意由 qa-verify 定義。

## 動作詞彙表

每條步驟由動作、欄位、值、目標、URL、注意組成。動作決定了其他欄位是否需要填寫。

### navigate
**語意**：用 URL 導入頁面
- **欄位**：null
- **值**：null
- **目標**：null
- **url**：目標 URL
- **注意**：null

例子：`navigate(url=https://<your-app>/orders/category)`

### click
**語意**：點擊 DOM 上的可點按元素（按鈕、連結、表格列、複選框）
- **欄位**：可選，若要點的是欄位內的控制項則填欄位名
- **值**：null
- **目標**：selector 或可讀元素標籤（按鈕文字、表格欄位值）
- **url**：null
- **注意**：null

例子：`click(target=新增按鈕)`、`click(欄位=分類代碼, target=下拉清單)`

### fill
**語意**：空欄＝直接替換。**欄位已有值時**，`mcp__chrome-devtools__fill` 是附加不是取代（實測推翻舊文件
「工具本身是整欄替換」的說法）——先 `click` 該欄取得焦點，再 `Control+A` 全選，才 `fill` 新值。
- **欄位**：欄位名（必）
- **值**：要填的值（必）
- **目標**：null
- **url**：null
- **注意**：null（若欄位已有值，操作機制寫「先全選」即可，不寫觀察結果）

例子：`fill(欄位=訂單分類代碼, 值=QA-001)`；欄位已有值：`click(欄位=訂單分類代碼, target=輸入框)` → `press(值=Control+A)` → `fill(欄位=訂單分類代碼, 值=QA-001)`

### fill_combobox
**語意**：下拉選擇框的組合流程。先 fill 文字，再從 select_option 的候選項中選擇。
- **欄位**：欄位名（必）
- **值**：初始文字（必）
- **目標**：最終選中的項目值或標籤
- **url**：null
- **注意**：null

例子：`fill_combobox(欄位=訂單分類, 值=QA, 目標=QA-訂單類)`

### select_option
**語意**：從下拉清單選項中選擇（通常在 fill_combobox 之後）
- **欄位**：欄位名（必）
- **值**：null
- **目標**：要選的項目標籤或值
- **url**：null
- **注意**：null

例子：`select_option(欄位=訂單分類, 目標=QA-標準訂單類)`

### press
**語意**：按下鍵盤按鍵（Enter、Tab、Escape）
- **欄位**：可選，若要在特定欄位按鍵則填欄位名
- **值**：按鍵名（Enter、Tab、Escape 等）
- **目標**：null
- **url**：null
- **注意**：null

例子：`press(值=Enter)`、`press(欄位=備註, 值=Tab)`

### observe
**語意**：觀察并記錄頁面狀態。讀取欄位值、訊息、視覺標記、網路請求等。
- **欄位**：null
- **值**：null
- **目標**：觀察對象，寫成可讀的值或狀態名稱（不寫 selector）
- **url**：null
- **注意**：null

例子：`observe(目標=訂單分類代碼欄位值)`、`observe(目標=保存成功訊息)`、`observe(目標=錯誤訊息位置)`

## 四條注意事項

1. **fill 對有值欄位是附加，不是替換**：`mcp__chrome-devtools__fill` 對空欄是直接替換；對已有值的欄位是
   **附加**（實測，推翻舊版「工具本身是整欄替換」的說法）。要修改既有值時，先 `click` 該欄
   拿到焦點，再 `press(值=Control+A)` 全選，才 `fill` 新值，達成真正的替換效果。

2. **combobox 先 fill 再 select_option**：下拉選擇框的操作須遵循順序：先 fill 輸入文字（篩選候選），再 select_option 從篩選後的候選項選擇。兩步是同一個邏輯操作，不能顛倒或跳過。

3. **observe 的目標寫成可讀值的東西**：不要寫 CSS selector 或 DOM path。寫欄位名、訊息文字、按鈕標籤、狀態名稱等人類能直接理解的概念。讓觀察記錄能被非技術人員檢視。

4. **頁面有全域搜尋框時，用該列容器定位輸入框**：全域搜尋／篩選欄位常與目標欄位同名或相似，若用
   `querySelectorAll` 取第一個非 readonly input 會誤填到全域搜尋框（實測兩次假結果）。一律先定位該筆
   資料所在的列／表單容器（如該筆記錄的 `<tr>` 或對話框 DOM 子樹），再從容器內找目標欄位，鎖定 uid 而非
   猜第一個符合條件的元素。

## 操作判準：步驟失敗次數 vs 記錄讀值次數

執行過程中會遇到兩類計數需求：

**步驟失敗次數**：因步驟本身寫得不夠 precise 或不完整而需要額外嘗試的次數。
- 判準：「如果步驟寫得更完整、更 precise，我就不需要做這一次」
- 例子：步驟寫「fill 訂單分類」但沒指明要先清空，執行時發現值沒覆蓋需要手動清空→1 次失敗
- 例子：步驟寫「click 按鈕」但按鈕在頁面上找不到，嘗試捲動頁面或等待元素出現→1 次失敗

**記錄讀值次數**：純粹為了填寫輸出格式（如欄位變化、訊息、視覺標記）而進行的 DOM 讀取或網路查詢。
- 判準：「即使步驟再完整，我仍然無法避免做這一次讀取」
- 例子：步驟寫「fill 訂單分類代碼、值 QA-001」，為了記錄「欄位變化」需要用 `evaluate_script` 讀 DOM value→1 次讀值
- 例子：步驟寫「click 保存」，為了記錄網路請求需要查 `list_network_requests` 的 status code→1 次讀值

兩者要分開統計。前者代表步驟質量，後者代表記錄成本，它們回答不同的問題。
