# 三份產出

三份產出的分工表與八段議程的分鐘配置在 SKILL.md Step 5。這裡只寫各章要放什麼。

## 三份互相指路的做法

報表抬頭放簡報網址＋明細網址；明細抬頭指回報表，並在開頭以目錄表標明
「每張清單對應報表哪一節」。三份的檔名／標題一律用**會議日**，對得起來。

## 各章內容

| 章節 | 要放什麼 |
|------|---------|
| 上週定調 | 一句話＋三個數字。**唯一要唸出來的段落** |
| 上次待辦兌現 | 對照上一份的「待辦事項彙整」，逐條標達成／未達，未達講原因不補交 |
| 各案進度 | 泳道圖，看每案卡在第幾棒 |
| 產能與時間 | 產能 vs 需求錯配、開發段 vs 驗收段耗時 |
| 卡點決策 | 每張卡＝現象（數據）／影響（誰被卡住）／選項 A-C／決策人＿期限＿ |
| 本週承諾 | 只押三件，每件標主責 |
| 臨時動議 | 預留議題（撈資料時發現、排不進議程的）＋現場登記空表 |
| 待辦事項彙整 | 來源／負責人／期限／完成四欄，最後一列留給臨時動議 |

已完成的事**貼著讓人看，不逐項唸**，一句話帶過。

## 敘事原則

- **主軸是客戶／案子，不是團隊**。主管問「某客戶什麼時候能收」，不是「後端做了幾張」。
- **名稱用功能名＋代碼**（「出貨作業（{功能代碼}）」），不用票號。
- **卡點寫成決策卡**：現象（數據）／影響（誰被卡住）／選項（A/B/C）／決策人＿期限＿。
  只寫「積壓 N 項」沒人會動；給選項和空格才有人認領。
- **人力講配置不講考績**：報「哪一棒缺人」，不報「誰做幾張」。個人層級留給存檔版。

## 會議簡報（HTML）

版面骨架＝**議程的分鐘預算**：左側標尺標每節佔幾分鐘，加總 30。
這個結構裝置編碼的是真實約束，不是裝飾。

**數字可點開**：每個統計數字是 `<button data-k="...">`，點擊從底部滑出抽屜，
列出票號／標題／負責人／meta，整列連往 `https://linear.app/<workspace>/issue/<ID>`。
資料以 `<script type="application/json">` 內嵌，**不要外部請求**（會議室可能沒網路）。

頁面載入時自動比對每個按鈕顯示值與其清單長度，不符就把該數字標紅並在 title 提示。

其餘版面規範（主題、字級、深淺色）依 `artifact-design`。

## Linear 會議文件

用 ```mermaid 圖（Linear 原生支援，等同編輯器的 `/diagram`）。四張：

1. **會議流程**：八段議程橫向串接，卡點標紅、臨時動議與待辦標綠
2. **全線存量**：需求→開發→測試→待驗收→完成，被擋的支線用虛線
3. **各案泳道**：`flowchart TB` ＋ 每案一個 `subgraph`（內含 `direction LR`），
   節點依狀態上色（綠完成／黃進行／灰未起）
4. **本週押三件事**：押注→預期效果

長條比較（產能錯配、耗時分桶）**用方塊字元表格**（`█████ 34`），
不要用 mermaid 的 `xychart-beta`——版本支援不確定。

## Linear 票務明細

開頭放目錄表：清單名／項數／對應報表哪一節。
超大清單（測試中／待驗收／需求中）**不列**，改指向簡報的可點數字，
並註明可在 Linear 用狀態篩選。

順手標出撈資料時發現的異常（重複票、逾期數月未動的高影響票），
放在對應清單後面當備註——那是 PM 會想知道但沒人會主動報的東西。
