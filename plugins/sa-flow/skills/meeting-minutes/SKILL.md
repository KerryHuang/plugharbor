# 會議記錄

> 非 Claude Code（如 Pi）執行時，先讀 `../../references/harness-terms.md`（相對本檔；Claude Code 為 `${CLAUDE_PLUGIN_ROOT}/references/harness-terms.md`，照字面執行可略過），把 Claude 專屬工具與路徑換成對應項。

記錄與整理會議——客戶／部門內部／研討會／學習。專注三件事：**會議中即時記錄**、**會後摘要**、**待辦事項**。可選在整理階段請 `domain-advisor` 全文審。

**不做**：主動備會、開 Linear 票、自動接需求流程、語音轉錄（輸入一律是使用者貼入的文字）。

**下游**：記錄要分類開票 → `sa-flow:issue-triage`；累積多場記錄要盤「已知什麼、還缺什麼」
或準備下一場訪談 → `sa-flow:interview-prep`。

**互動原則**：互動詢問依 `${CLAUDE_PLUGIN_ROOT}/references/shared-preludes.md` §互動詢問規範（一次一題、能選就不打字）。

## 0. 選模式

用 `AskUserQuestion` 問本次用哪種：

| 模式 | 情境 |
|------|------|
| **即時記錄** | 邊開會邊貼片段 |
| **事後整理** | 已有整份逐字稿／草稿 |

## 1. 收集 Metadata（兩模式共用）

逐欄問（依互動詢問規範）。順序與選項建議：

1. **會議主題**：無合適預設時給一個推測選項 + Other。
2. **會議類型**：客戶 / 部門內部 / 研討會 / 學習（四選一，寫入會議記錄 metadata）。
3. **時間**：預設「今天」+ 常見時段（上午 10:00／下午 14:00／現在）+ Other 自訂。
4. **地點**：常見選項（線上／公司會議室／客戶端）+ Other。
5. **記錄人**：**預設當前使用者為首選項** + Other。
6. **會議目標**：常見選項（需求釐清／驗收／進度同步／教育訓練）+ Other。
7. **參與者**（可省）：附「略過」選項 + Other。
8. **議程**（可省）：附「略過」選項 + Other。
9. **參考資料 / 上次會議**（可省）：附「略過」選項 + Other。

可省欄位一律附「略過」。即時模式在**建骨架檔前**收；事後模式可在整理階段一併補。議程／驗收範圍／出席等，若使用者貼**圖或表格**，擷取內容填入對應章節（見 conventions §6）。

> **落檔位置**：`{docs-root}` 下專案既有的會議記錄目錄（`{docs-root}` 由專案 CLAUDE.md 設定，未設定為 `docs/`）。
> 找不到既有會議記錄目錄時**先問使用者**，不要自建第一階目錄。
> 會議記錄常含談話內容，是否進版控由專案決定；不確定時提醒使用者先確認 `.gitignore`。

## 2A. 即時記錄流程（逐步落檔）

1. **決定落檔**：依上方落檔位置決定目錄；`AskUserQuestion` 問檔名（預設 `YYYY-MM-DD-主題`）。
2. **建骨架檔**：讀 `${CLAUDE_PLUGIN_ROOT}/templates/meeting-minutes.md`，填入 metadata、清空記錄區，`Write` 到目標路徑。
3. **記錄迴圈**：使用者逐段貼入口述／討論片段，每段**整理並改寫**後 `Edit` 更新檔案（逐步落檔，session 中斷不全失）。慣例見 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/recording-conventions.md`：
   - **議題單位**：一般用討論主題；系統 Demo／驗收／教育訓練類用**功能模組**（標題可帶功能代碼／舊系統對照）。
   - **同議題追加、就地修正／刪除／歸屬校正**：新片段屬既有議題則併入不另開段；修正／刪除既有條目直接改寫／移除；模組歸屬錯誤時移到正確議題並合併。摘要／待辦已寫出後記錄再變動，要回頭刷新其衍生數字。
   - **狀態標註**：每條依性質標 `缺陷 / 待確認 / 下一階段交付`（改善需求為預設、可不標），用詞精準勿混用。
   - **文句品質（核心）**：**不照口語／條列原樣搬**，改寫成清楚、完整、一般人一看就懂的「現況 → 期望」句式（例：「訂單日期往上」→「查詢區把訂單日期欄位移到最上方，方便優先使用」）；抓意思、不臆造未提到的事實。
4. **中途整理／去重（可隨時觸發）**：使用者說「整理一版／去重」時，依 conventions §4 做跨模組去重、合併同題衝突、交叉引用因果，並簡述異動；不進整理階段、不寫摘要。
5. 使用者說「散會 / 結束 / 整理」→ 進入 §3（回填同一檔）。

## 2B. 事後整理流程

1. 收使用者貼入的整份逐字稿 / 草稿。
2. 直接進 §3。
3. 整理完成後才 `AskUserQuestion` 問落檔位置（目錄 → 檔名），`Write` 寫檔。

## 3. 整理階段（兩模式共用）

### 3.1 收斂產出

<law>
**事後整理模式（§2B）派 agent，即時記錄模式（§2A）不派。**

事後模式的輸入是整份逐字稿——量大、且對「判讀待辦歸屬」無用，派出去才不會擠爆 context：

```
subagent_type: "sa-flow:report-writer"
prompt: |
  report_type: minutes
  out_path: {會議記錄絕對路徑}
  template: ${CLAUDE_PLUGIN_ROOT}/templates/meeting-minutes.md
  dataset: {逐字稿／草稿檔絕對路徑}
  period: {會議 metadata：主題／類型／時間／地點／記錄人／目標／參與者}
  constraints: |
    **不照口語原樣搬**——改寫成清楚、完整、一般人一看就懂的「現況 → 期望」句式
      （例：「訂單日期往上」→「查詢區把訂單日期欄位移到最上方，方便優先使用」）
    抓意思、**不臆造未提到的事實**
    每條依性質標 `缺陷 / 待確認 / 下一階段交付`（改善需求為預設、可不標），用詞精準勿混用
    結論與決議置頂、一段 ≤3 句；待辦表格緊接其後；過程紀錄後置
  siblings: 無
```

**即時模式已經逐段 Edit 落檔在骨架檔裡**，此處只需 append 結論與待辦——
主 session 直接做，派工反而要把已寫好的內容再傳一次。
</law>

依範本區塊產出 / 回填（**文句品質同 §2A.3：全部改寫成清楚易讀、現況→期望的句式，不照口語原樣搬**）：

- **結論與決議**（置頂，一段 ≤3 句）：整場決議與重點，結論先講。
- **待辦表格**（緊接結論）：任務 / 負責人 / 完成時間 / 狀態；**依狀態標籤分流**（缺陷→修復、下一階段交付→next-phase backlog、待確認→釐清、改善→評估），見 conventions §5。
- **過程紀錄**（後置）：逐議題的結論、重要意見、擱置 / 待追蹤。

### 3.2 顧問審閱（可選）

依 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/advisor-review.md`：
**先問使用者要不要上**，說要才派 `sa-flow:domain-advisor`（`mode: review`，以完整記錄為證據），整併回饋寫進「顧問建議 / 待釐清」區塊。未審閱則刪除該區塊。

### 3.3 發布到筆記服務（可選）

僅在專案有設定筆記發布服務（專案 CLAUDE.md 載明的發布工具或 MCP）時進行；**先檢查是否可用，不可用則只落檔、不提發布**。
本機檔案已寫入成功後，用 `AskUserQuestion` 問要不要發布（預設「發布」，另附「不發布」）——
會議記錄常含談話內容，**不靜默送出**。使用者說要，才發布**整份會議記錄**（與本機檔內容一致，
不另做精簡版）。發布失敗不阻斷落檔，也不回頭改已寫好的檔。

### 3.4 收尾

回報最終檔案路徑（即時模式 = 回填骨架檔；事後模式 = 新寫檔），以及筆記網址（若已發布）。

完成後依動線用 AskUserQuestion 建議下一步：需求還沒收斂、要準備下一輪訪談 → `sa-flow:interview-prep`；會中有一批回饋要分類開票 → `sa-flow:issue-triage`（會議記錄只記錄，不分類也不開票）；使用者同意才接著跑，不自動執行。

## 錯誤處理

| 情境 | 處理 |
|------|------|
| 使用者未提供會議類型 | `AskUserQuestion` 補問四選一 |
| 目標目錄不存在 | 確認使用者同意後 `mkdir -p` 該目錄 |
| 顧問回饋為空 / 派發失敗 | 記錄「顧問無補充」或跳過，不阻斷落檔 |
| 筆記服務未登入 / 發布失敗 | 印出訊息請使用者處理後重發，本機檔案已落檔不受影響 |
