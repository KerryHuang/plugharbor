# 交接再清空

長 session 每一輪都整份重送 context。任務還沒做完、但 context 已經很大時，
與其帶著整段探索過程繼續跑，不如把**接手需要的結論**寫成一頁，`/clear` 後讓新 session 讀檔接著做。

## Step 1：決定交接檔位置

- 專案規則有規定跨 session 暫存區（例如 `.tmp/<YYYYMMDD>-<slug>/`）→ 照它放，檔名 `handoff.md`。
- 沒有 → `~/.claude/handoffs/<YYYYMMDD>-<slug>.md`。
- slug 取 `$ARGUMENTS`；沒給就依任務內容取，全小寫 ASCII、連字號。
- 同一路徑已有交接檔 → 先讀，延續它的結構改寫，不另開一份。

## Step 2：寫交接檔

固定五節，每節只寫結論與指路，**不貼檔案全文、工具輸出、討論過程**——
新 session 需要時自己讀原始檔，那些正是要清掉的部分。

```markdown
# 交接：<任務名>（<日期 時間>）

## 目標與驗收標準
## 已完成（含 commit hash／檔案路徑／版本號）
## 已拍板的決定（下一棒不要重問）
## 試過但排除的方向（與原因）
## 下一步（第一個動作要具體到檔案或指令）

## 收工清理
使用者說「收工」「完工」「結束此對話」之類，或驗收標準達成、回報完成時，在同一輪刪除本檔；
所在資料夾若只為這次交接而開，連資料夾一起刪。資料夾內使用者提供的輸入檔不刪，列出來問使用者。
使用者只是結束某一段、還要接著做別的（「這段收工，接下來做 B」），不刪。
```

寫完自己重讀一次，問：「只看這份檔，接手的人能不能直接開始第一步？」不能就補。
未 commit 的改動要列出檔案清單，提醒接手者先看 `git status`。

## Step 3：印出接續句並收尾

回報三行，最後一行用程式碼區塊包起來方便複製：

1. 交接檔絕對路徑。
2. 建議動作：`/rename <slug>` → `/clear`。
3. 新 session 要貼的第一句：

```
讀 <交接檔絕對路徑>，從「下一步」接著做；完工或我說收工時，照檔末「收工清理」刪掉它。
```

不要自己執行 `/clear`（做不到，也不該替使用者決定）。交接檔在任務完成前不刪；完成後由接手的 session 依「收工清理」刪除——指示寫在檔內與接續句，接手者一開工就讀到，不另設 hook。
