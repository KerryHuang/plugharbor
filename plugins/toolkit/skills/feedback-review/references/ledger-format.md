# 帳本格式

帳本是 markdown，第一次記帳時建立。user 層改動記在 `~/.claude/feedback-loop/ledger.md`，
專案層改動記在該專案的 `.claude/feedback-ledger.md`。每條改動一個小節（不用表格：「改了什麼」常常多行）。

```markdown
# 回饋改動帳本

由 /feedback-review 維護。每條改動經人審核准；狀態：觀察中／✅ 生效／❌ 無效。

## 2026-01-15｜先查既有慣例再選工具

- 來源佇列：20260110093012-a1b2c3, 20260112141500-d4e5f6
- 目標檔：`.claude/rules/tooling.md`
- 改了什麼：新增一條「選測試工具前先看專案既有 script」；刪除重複的舊條「優先用 X」
- 強制方式：文字（升級時改成 `guard <名稱>`／`腳本 <路徑>`／`測試 <路徑>`）
- 預期效果：不再出現「改用專案的 script」這類糾正
- 驗效訊號：matched 含「改用」且原話提到測試／script 的糾正
- 狀態：觀察中
- 驗效紀錄：
  - 2026-01-22 ⏳ 改動後 7 天，未滿觀察期
```

## 驗效判準

只看**改動日之後**（`--since <改動日>`，不含當日）的佇列與 archive；專案帳本只算 `cwd` 落在該專案內的筆數。

- **❌ 無效**：出現 ≥ 1 筆符合驗效訊號的糾正。記下那幾筆 id。
- **✅ 生效**：距改動 ≥ 14 天、沒有符合訊號的糾正，**且**同期間佇列＋archive 有其他糾正
  （證明 hook 有在記、這段時間有在用；專案帳本要求同專案內有）。
- **⏳ 樣本不足**：其餘情況（未滿 14 天，或同期間完全沒有任何糾正、無從判斷），維持觀察中。

佇列只記「有糾正」的 session，所以不用 session 數當樣本量——改得越有效、糾正越少，
用 session 數會讓 ✅ 越難成立。

判定寫進「驗效紀錄」追加一行，不改寫舊紀錄；狀態欄改成最新判定。
❌ 的條目在本輪自成一群優先重提；核准新改法後，舊條目維持 ❌ 並註明由哪一條取代。
