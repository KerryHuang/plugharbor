# 為什麼一律人審、只增量、要驗效

- **自動改規則會劣化**：研究顯示 context 檔（AGENTS.md／CLAUDE.md 類）整體不提升任務成功率、
  成本約增 20%，自動生成的更差（arXiv 2602.11988）。規則要人審，而且要做減法。
- **整檔重寫會 context collapse**：反覆以 LLM 重寫整份 playbook，細節會被壓縮掉、品質崩落
  （ACE，arXiv 2510.04618）。只做局部增量 Edit。
- **沒驗效就不知道改了有沒有用**：規則越加越多但同類糾正照樣出現，是最常見的失敗形態。
  帳本＋下輪 Check 讓每條改動都有「生效／無效」的結論，無效的拿出來重想，而不是再疊一條。
- **加一條附一個可刪候選**：常駐 context 每個 session 都付費。只加不減，規則會長到沒人讀得完，
  agent 也開始互相矛盾地遵守。

參考實作：hook 佇列＋人審指令的做法（如 claude-reflect）、把解法沉澱成文件的做法（如 compound-engineering）。
