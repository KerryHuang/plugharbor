# 交棒握手

context 快滿、整案需要換主將，或原 CLI 無法繼續時，用這個流程交給新 session。長任務每完成一個階段，就更新同一份交接檔；第一次建立時，把絕對路徑寫進任務紀錄或回報給操作者，讓舊主將無法回應時也找得到。

## 步驟

1. **產交接內容**：可以沿用 `toolkit:handoff` 的交接檔格式；定期記錄和換主將時只寫檔，不執行它的 `/clear` 流程。上限 8000 字元，超過就把細節留在檔案、交接內容只放路徑。必含：
   - 目標與目前進度（已完成／進行中／下一步）。
   - 已定案的決定與已排除的方向（不要讓對方重問、重走）。
   - 相關檔案路徑、分支、未 commit 的改動。
   - 已跑的驗收、結果或證據路徑，以及未驗證事項。
   - 待使用者決定的事項。
2. **停寫再送出**：舊主將在安全點停止寫入，確認會碰同一批檔案或共用資源的 worker 和背景命令也已停寫。更新交接檔，再把工作區內的絕對路徑交給對方：
   - Claude Code 對 Claude Code：`SendMessage`，內容是「請先唯讀核對交接檔 <路徑> 與現況，回覆『已接手：<一句話摘要>』，收到可以開始的通知後再改檔或寫入共享資源」。
   - 其他 CLI：用 agent-dispatch 的長任務模式開新 worker，沿用上述唯讀與等通知的指示；只允許先將「已接手：…」寫入指定的確認檔，收到開工通知前不得做其他寫入。
3. **等確認**：接手方先唯讀核對現況並回覆「已接手：…」（訊息或確認檔）。舊主將或執行交接的操作者核對摘要相符後，才通知接手方可以開始寫入。此後舊主將只回答問題，不再改同一批檔案。
4. **沒確認**：送不到、對方沒回、或摘要對不上，交接就未完成。取消這次交接，接手方保持唯讀；沒有發過開工通知且確認沒有第二個寫入者，原主將才可復工。告訴使用者失敗原因，不重複送出同一份交接。

## 舊主將無法回應

由操作者確認舊主將和相關 worker、背景命令已停寫，再交付最近的交接紀錄，依步驟 3 確認並交出所有權。接手方先比對紀錄之後的實際檔案與任務狀態；有不一致就先釐清。若無法確認已停寫，就維持唯讀，暫停移交。
