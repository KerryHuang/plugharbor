# 交棒握手

context 快滿、要把進行中的工作交給新 session（或另一個 CLI）時照這個做。目的是不讓工作在交接時掉在地上：沒確認收到就不算交出。

## 步驟

1. **產交接內容**：有 `toolkit:handoff` 就用它產；沒有就自己寫。上限 8000 字元，超過就把細節留在檔案、交接內容只放路徑。必含：
   - 目標與目前進度（已完成／進行中／下一步）。
   - 已定案的決定與已排除的方向（不要讓對方重問、重走）。
   - 相關檔案路徑、分支、未 commit 的改動。
   - 待使用者決定的事項。
2. **送出**：寫進交接檔（工作區內的絕對路徑），再把路徑交給對方：
   - Claude Code 對 Claude Code：`SendMessage`，內容是「請接手，交接檔：<路徑>，讀完回覆『已接手：<一句話摘要>』」。
   - 其他 CLI：用 agent-dispatch 的長任務模式開新 worker，prompt 同上，要它把「已接手：…」寫進指定的確認檔。
3. **等確認**：收到「已接手：…」（訊息或確認檔），而且摘要跟交接內容相符，才算交出。之後你只回答對方的問題，不再改同一批檔案。
4. **沒確認**：送不到、對方沒回、或摘要對不上 → 交接失敗，所有權留在你這裡。告訴使用者交接失敗與原因，繼續由你做，或請使用者決定下一步。不要重複送出同一份交接。
