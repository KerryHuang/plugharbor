# 週報模板骨架

落檔到 `<OUT>/YYYY-MM-DD-ai雷達.md`（`<OUT>` 見 SKILL.md「輸出位置」），套用以下結構。

```markdown
# AI 情報雷達 — YYYY-MM-DD（回溯 N 天）

> 掃描區間：YYYY-MM-DD ~ YYYY-MM-DD ｜ 引擎：輕量 / 含 --deep <區塊>

## 1. 大廠更新與教學
| 主題 | 來源（連結 + 日期） | 可信度 | 重點 / 對本專案的影響 |
|------|------|--------|------|
| Claude Code skill/rule/hook/script 規範變更 | … | 官方 | … |
| 其他大廠（OpenAI/Google/Cursor…） | … | 官方 | … |

## 2. 最佳實踐（軟體工程 / vibe coding + AI）
| 做法 | 來源（連結 + 日期） | 可信度 | 摘要 |
|------|------|--------|------|
| … | … | 社群 | … |

## 3. 反查 agent system 最佳化（建議 + 行動草案）
> 不自動套用；要改交棒 superpowers:writing-skills。

| # | 對應發現 | 目標檔（user 層或專案） | 建議 | 具體行動草案 |
|---|---------|-------------|------|-------------|
| 1 | （區塊1/2 哪一條） | `~/.claude/...` 或專案 `.claude/...` | … | 要改什麼、怎麼改 |

## 4. Marketplace / Plugin 排行
| 名稱 | 類型 | 連結 | 熱門度（星/討論/推薦來源） | 一句話用途 |
|------|------|------|------|------|
| … | marketplace / plugin | … | … | … |

## 本週 TL;DR
- 最值得注意的 3 件事：…
- 建議本週採取的行動：…
```

## 注意

- 每列務必填來源連結與日期；缺來源的聲明不要寫進報告。
- 區塊 3 至少嘗試找出 1–3 個可落地的最佳化點；真的沒有就明說「本週無」。
