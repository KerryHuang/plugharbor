# 上線檢查

push 就是對外發布。使用者沒明說要上線就不做。
push 的分支、部署平台、站台網址、測試指令都**依專案 rule**（`.claude/rules/` 或 `AGENTS.md`）；沒有就問使用者，不自行猜。

## 1. 上線前檢查

依序確認，任何一項失敗就停下來修，不上線：

1. `git status --short`：沒有漏 commit 的檔案，也沒有不該提交的檔案。
2. 草稿標記已照使用者指示拿掉（或確實保留）。
3. 個資掃描：已 staged／已 commit 的內容沒有個人 email、手機、住址、內部網址、金鑰；專案規則列了其他紅線（例如孩子的名字、公司名）也一併掃。可用 `git grep --cached -nE '<pattern>'`。
4. 專案規則指定的測試、型別檢查、build 全部通過。
5. 文章裡的連結與圖片在本機預覽可開。

## 2. 同步遠端

push 前先 `git fetch`，確認遠端沒有本機沒有的新 commit。
若不能 fast-forward（兩邊都有新 commit），停下來問使用者，不自行 rebase 或 force push。

## 3. 推上去

照專案規則的分支流程 push。不使用 `--force`，不略過 hook。

## 4. 驗證

部署平台通常需要 1–2 分鐘。等待後抓改動的頁面，確認新內容的特徵字串在裡面：

```bash
curl -s <站台網址>/<路徑>/ | grep -c '<改動的特徵字串>'
```

沒更新就再等一分鐘重試；約 5 分鐘後仍沒更新，回報使用者去看部署平台的建置紀錄。

## 回報

一句話：上線了什麼、網址、驗證結果。
