# 暫存分層

臨時產物分兩層，判準是「誰要看」：

| 層 | 放什麼 | 位置 |
|---|---|---|
| session scratchpad | 只有自己這個 session 用、不給人看的中間物（一次性腳本、解析暫存、驗證 log） | harness 提供的 session 暫存目錄；沒有就用系統暫存目錄下自己開的一層 |
| 專案 `.tmp/` | 要給使用者看、跨 agent／跨 session 共用、或 skill 的工作區 | repo（或 workspace）根目錄的 `.tmp/`，**必須已 gitignore** |

**禁止**在 repo 根目錄或子模組裡散建隨機命名的暫存資料夾。

## 🔴 `.tmp/` 下不准有裸檔

一律先開一層資料夾再寫檔。裸檔看不出屬於哪件事、能不能刪——這是 `.tmp` 變亂的唯一根因：幾週後同一層混著五六件不相干任務的檔，誰也不敢刪。

## 兩區

| 區 | 命名 | 生命週期 |
|---|---|---|
| skill 工作區 | `.tmp/<skill-slug>/`，路徑寫死在 skill 裡 | 每輪覆蓋，只留最新一次；**不要改名或搬動** |
| ad-hoc 任務區 | `.tmp/<YYYYMMDD>-<slug>/`，日期取開工日 | 任務結束當輪即刪；跨 session 者留到該任務結案 |

### 命名

- 有票號就帶票號：`20260907-abc123-cutover`；沒票就寫對象＋動作：`20260904-orders-parse`。
- **全小寫、連字號、只用 ASCII**——中文或空白檔名在 Windows Git Bash、各種 CLI 的重導向與編碼轉換會出事。
- 有先後的檔用 `NN-` 前綴（`01-restore.sql`、`02-baseline.sql`），腳本與其 log 同名不同副檔名。
- 超過 5 個檔或跨 session → 放一份 `README.md`：一行用途、票號、可刪日期。

### 三條禁令

1. 裸檔。
2. 版本尾巴（`convert-v2.sql`、`fix2.sql`）——同一份就地改；真要留舊版放該資料夾的 `archive/`。
3. 非 ASCII 檔名。

## 逃生口：它其實不是暫存檔

判準一句話：**下週還會再打開嗎？** 會 → 當下就搬走，留在 `.tmp` 等於宣告「隨時可以被清掉」。

| 東西 | 搬去 |
|---|---|
| 對外產出、規格、分析結論 | 專案的文件目錄 |
| 反覆用的小工具 | 專案的工具目錄（如 `.claude/tools/`、`scripts/`） |
| 跨 session 的知識、踩雷紀錄 | memory 或專案 rules |

## 清理

- **任務結束時，在回報完成的同一輪刪掉自己開的資料夾**，不拖到下次；空資料夾直接刪。
- **例外：被派出去的 worker 不自己刪**——把路徑列在結果檔，由派工的主 session 收工時統一清。worker 的 `rm -rf` 常撞權限確認，會讓 worker 卡在確認畫面沒人理。
- 清理範圍只限**交棒檔或派工紀錄列出的暫存**，以及自己開的資料夾。**使用者放進來的輸入（截圖、prompt 檔、樣本）不刪**；來源不明的留著，回報時列給使用者決定。`rm` 不進垃圾桶，刪錯救不回來。
- 開新任務前看到兩週以上沒動的 ad-hoc 資料夾，列出來問要不要清，不自行刪。
