# 受眾附錄：兒童

使用者明確說明受眾是兒童，或專案 README／設定標明兒童受眾時載入；一般專案不套用。供 `designing-ui`、`auditing-ui` 共用。

預設對象是小一（6–7 歲）、平板橫放、手指點。專案若有自己的設定，先讀專案的 `.claude/skills/designing-ui/this-app.md`（舊專案在 `.claude/skills/designing-kid-ui/this-app.md`）或 `.claude/rules/` 裡的 app 版面規則（裝置、元件在哪個檔案、這個 app 的坑）；都沒有，就請使用者提供年齡層和裝置再開始。

## 兒童專屬原則

1. **對象**：手指點、短句、口語；畫面文字用使用者的語言，識字量低的年齡層要加注音或拼音，破音字手動標；按鈕、標題、地名一行放完，只有句子可以折。
2. **一步一件事**：一個畫面只問一個問題，大按鈕按了就往下，左上 ◀ 回上一步，不疊多層選單。
3. **念出來**：畫面打開就念它要做什麼；念題開關關掉不念；系統提示（存檔失敗）不念。
4. **點擊回饋**：點了一定有反應（選取音效或畫面變化）；剛打開 300ms 內的點擊不算。
5. **語音排隊**：要立刻停的地方（離開、錄音前、亮字對時間）一律走專案封裝的語音 stop，不直接 `speechSynthesis.cancel()`；錄音時不念。
6. **錯了怎麼辦**：孩子答錯說「再想想看」並念出來，不扣分、不跳警告；系統錯誤給家長一條提示，流程照常。
7. **遮罩分兩種**：題目卡不擋下面的按鈕，彈窗才擋整個畫面；離開場景清掉兩者並停語音。
8. **視覺**：標題深色實心字，任何主題都不加 text-shadow（注音會糊）；顏色用 CSS 變數，每個主題都看過對比。
9. **版面**：多個裝置尺寸 × 多語言都要跑過，最矮的尺寸親眼看截圖；做法見下方「版面尺寸」。
10. **素材**：不用別人的商標或受保護素材，新素材附授權檔。

## 文字

- 短標籤（按鈕、標題、名稱）不折行；只有句子可以折。詩、歌詞照句讀換行。
- 帶注音的多行文字 `line-height` ≥ 1.6；有字的元素字級 ≥ 10px。
- 注音字約 1.5em 寬，空間固定的格子要讓字級跟寬度走（例如 `(格寬 - 邊框) / 字數`），不要固定字級。
- 圓或方塊裡放好幾個字，用 `min-width` 加 `padding`，不用固定寬（會被擠成直排）。
- 注音字不要用 text-shadow 疊外框：筆畫細，8 方向陰影一疊就糊。

## 念題與語音

- 畫面、選單、彈窗打開時念一句要做什麼；結算念結果；第一次碰到不直覺的操作要念提示。
- 正在念的念完，新句子只留最新一句排隊；引擎沒在念就直接念；重聽鍵也排隊，不先停。
- 要立刻停一律走封裝的 stop（先清排隊再 cancel）。
- 輪到孩子、電腦思考中，畫面和語音都要有提示。

## 點擊回饋與防誤觸

- 每顆按鈕有回饋，優先用同一個選取音效。
- 用一個共用 guard：畫面、步驟、彈窗新建後 300ms 內的點擊不算；換步驟重新起算；連結同時擋預設動作。
- 點擊區要夠大；放不下就擴大點擊區、不改外觀。按鈕底色不透明。

## 彈窗

- 彈窗擋整個畫面；題目卡不擋。
- 「看完就走」的面板（新功能、預覽、抽屜）可以點遮罩關；要做選擇的彈窗不能點遮罩關。
- 暫停框：「▶ 繼續」加寫明去哪的返回鍵；暫停要同時停流程、動畫、語音；分出勝負後拿掉暫停鍵。
- 結算念結果；輸了也鼓勵，不只播失敗音效；一個問題只問一次；結算時收掉比賽中的 HUD。

## 返回與關閉

- 返回一律左上 `◀`，關閉一律右上 `✖`。
- 除了第一次開機的必要步驟，每個畫面都要有返回路。
- 等外部事件（錄音、播放、權限）要有逾時和可以按的退路。

## 主題配色

- 標題深色實心字；各主題的標題色在該主題的最淺背景上量對比。
- 白字不要直接壓在淺色背景（天空、雲）上；要在最淺的背景上量。暗色主題也看。
- 開關關掉用同一套樣式（例如 `opacity: 0.6` 加灰階）。
- 背景分層的邊界不要有直線穿過畫面；換主題後裝飾逐一截圖看過。
- 主題「選擇」（含自動）和「實際主題」分開存；網址參數優先並寫回。

## 版面尺寸

- 先決定支援的方向（兒童 app 常只支援橫向）。最矮的情況通常是手機橫放扣掉瀏覽器工具列，約 325px 高。
- 改了版面，8 台裝置 ×（原尺寸＋扣掉瀏覽器工具列）＝ 16 個尺寸，中英文都要跑過，確認沒有被切掉、沒有重疊、沒有橫向捲動：

  | 裝置 | 尺寸 | 扣掉瀏覽器工具列 |
  |---|---|---|
  | iPhone SE | 667×375 | 667×325 |
  | iPhone 15 | 852×393 | 852×343 |
  | iPhone 15 Pro Max | 932×430 | 932×380 |
  | Pixel 7 | 915×412 | 915×362 |
  | iPad mini | 1133×744 | 1133×674 |
  | iPad Air 11" | 1180×820 | 1180×750 |
  | iPad Pro 13" | 1366×1024 | 1366×954 |
  | Galaxy Tab S9 | 1280×800 | 1280×730 |

  最矮的 667×325 要截圖親眼看；程式檢查回「沒問題」不代表沒破版。
- 字級和尺寸用 `clamp(最小, vh 或 vw, 最大)`；所有元素的「最小值」加起來常常就超過 325px 高，矮螢幕用 `@media (max-height: 500px)` 另外處理。
- 一排並列的東西寬度要同時受 vw 和 vh 限制，例如 `min(20vw, 38vh)`，只用 vw 加第四張卡就會被切掉。
- 疊放元素（標記、角色圖示、浮動鍵）不蓋字；同一排的鍵不疊；橫向捲動的卡片列要有捲動提示；emoji 圖示和方框一起置中。
- 用腳本（python、sed）改 CSS 之後一定看 `git diff`，巢狀 `@media` 這類錯誤型別檢查和測試都抓不到。

## 做新畫面的額外步驟

通用步驟之外，兒童受眾另加：

```
- [ ] 讀本附錄「要一致的元件」：有沒有現成元件（彈窗、大按鈕、◀、✖、開關、提示條、防誤觸），照它的做法寫
- [ ] 念題、點擊音效、300ms 防誤觸、短標籤
- [ ] DOM 測試（如 jsdom）測結構和點擊流程
- [ ] 瀏覽器實測：16 尺寸 × 中英文，667×325 截圖
- [ ] 改到「要一致的元件」→ 同一輪通知同系列的其他 app
```

## 要一致的元件

同系列 app 共用的元件規範。每個元件在本 app 的哪個檔案，見專案的 `this-app.md`（沒有就自己 grep）。以下數值是一組已驗證過的範例，沿用或換成自己的都可以，重點是同系列 app 一致。

| 元件 | 做法 |
|---|---|
| 標題 | 深紫實心字（範例 `#2b1d4e`），不加任何 text-shadow |
| 開關關掉 | `opacity: 0.6` 加灰階 |
| 範例（PWA）🔄 更新 | 提供手動更新入口；按下後全畫面遮罩鎖住並用短句顯示進度，連不上網路要念出原因、幾秒後自動解除；更新不能清掉孩子的進度 |
| 短標籤 | 按鈕、標題、地名一行放完 |
| 新功能通知 | 大功能上線時加一筆公告，首頁通知老玩家；小修正不加 |
| 範例（PWA）📲 安裝 | 只在尚未安裝的 iOS/iPadOS 瀏覽器分頁顯示小膠囊；點了跳說明框，用一兩句短話念出「分享 → 加入主畫面」的步驟；300ms 後點任何地方關閉並停語音 |
| 主題 | ☰ 選單「🎨 主題」打開大卡片選擇畫面（含「自動」），打開時念「選一個主題」、點卡片有選取音效、剛打開 300ms 內點卡片不算。**選擇**（`auto` 或主題 id）和**實際主題**分開：存檔、網址存的是選擇，預設 `auto`，`auto` 依本地月份換（開機判斷一次）；自動卡寫「現在：X」、✅ 標在選擇上。網址 `?theme=<選擇>` 優先並寫回；跨 app 連結帶選擇，對方認不得的 id 當 `auto`；各主題標題用米白實心字（範例 `#fff3e0`）、不加 text-shadow |

### 同系列 app 的一致性

- 改到上表元件，同一輪通知其他 app 的維護者或 session，附 commit、改了什麼。
- 不直接改其他 app 的 repo（對方可能正在改同一批檔案）；對方沒同步就在回報寫明。
- 新的共同做法或同意的差異寫回本附錄；共用檔改之前先問使用者。

### 常見的合理差異

同系列 app 不必完全相同的地方，先記下來，避免被當成不一致：

- 同一個功能的入口位置（例如「繼續上一局」放在流程第一步或一顆獨立按鈕）：各 app 依自己的流程決定。
- 首頁分區：各 app 的區數、區名、卡片內容和配色各自決定。
- 主題背景的實作：用繪圖引擎（會動）或 CSS 背景（裝飾停在固定位置）可以不同；全螢幕背景動畫在平板上很耗電，CSS 版建議靜態。
- 念題排隊：有跟讀、亮字照時間跑的 app，念之前先 stop，可以另外提供「忙碌中」查詢給其他流程等念完。

## 審查清單（兒童受眾加項）

每條一個可勾項，括號裡是怎麼查。`auditing-ui` 載入本附錄時，在通用清單之外加查這些。

### 文字與語音

- [ ] 短標籤一行放完，只有句子可以折；詩、歌詞照句讀換行（量測折行的腳本＋截圖）
- [ ] 畫面、選單、彈窗打開時念一句要做什麼；結算念結果（讀 `show*` 函式有沒有呼叫 `speak`）
- [ ] 第一次碰到不直覺的操作（例如點兩下才出牌）要念提示
- [ ] 輪到孩子、電腦思考中，畫面和語音都有提示
- [ ] 系統提示（存檔失敗）不念
- [ ] 要立刻停的地方走專案封裝的語音 stop，沒有直接 `speechSynthesis.cancel()`（grep）

### 互動

- [ ] 每個新畫面、步驟、彈窗都經過共用防誤觸 guard（grep guard 的使用處，對照 `show*`）
- [ ] 每顆按鈕有回饋，優先用同一個選取音效
- [ ] 返回左上 `◀`、關閉右上 `✖`；點遮罩能不能關照「要一致的元件」（grep 返回與關閉的符號）
- [ ] 除了第一次開機的必要步驟，每個畫面都有返回路
- [ ] 暫停會停流程、動畫、語音；分出勝負後沒有 ⏸
- [ ] 答錯、輸了都溫和鼓勵，不扣分、不跳警告
- [ ] 開關看得出開或關，關掉用同一套樣式
- [ ] 同類元件只用一個建構函式（例如 🔊 重聽鍵），沒有手刻第二份

### 視覺與版面

- [ ] 16 個尺寸 × 中英文，版面檢查腳本回報無問題，667×325 截圖親眼看過
- [ ] 有字的元素字級 ≥ 10px；帶注音的多行文字 `line-height` ≥ 1.6（版面量測腳本）
- [ ] 直接放在背景上的字在最淺的背景（原本主題的天空和雲）上看得清楚；暗色主題也看過
- [ ] 圓或方塊裡放字用 `min-width`＋`padding`，不用固定寬
- [ ] 疊放元素（標記／角色圖示、標記、浮動鍵）不蓋字；同一排的鍵不疊；裝飾避開文字（版面量測腳本）
- [ ] 按鈕底色不透明；點擊區夠大，放不下就擴大點擊區、不改外觀
- [ ] 橫向捲動的卡片列有捲動提示，文字離卡片邊 ≥ 4px
- [ ] emoji 圖示和方框一起置中
- [ ] 背景分層的邊界沒有直線穿過畫面；換主題後裝飾逐一截圖看過

### 失敗處理

- [ ] localStorage 讀寫都有 try/catch；`saveXxx()` 回 false 一律走統一的存檔失敗提示（grep `setItem(`、`save`）
- [ ] 讀到非空但解析失敗的存檔，先備份到 `.bak` 再回預設值
- [ ] 寫完立刻重新載入的流程（匯入、換主題）先確認寫入成功
- [ ] 音效、語音、動畫失敗不會丟錯擋住流程
- [ ] 清掉按鈕後等待外部事件（錄音、播放、權限）有逾時和可以按的退路

### 同系列一致

- [ ] 改到「要一致的元件」，同一輪通知同系列的其他 app，附 commit

## 常見坑

- **症狀**：標題的注音糊成一團。
  **原因**：用 text-shadow 疊 8 方向外框，注音筆畫細。
  **修法**：標題用深色實心字，不加 text-shadow。
- **症狀**：白字在天空、雲等淺色背景上看不見。
  **原因**：只在預設背景量對比。
  **修法**：在該主題最淺的背景上量，暗色主題也看。
- **症狀**：固定寬的圓裡放好幾個字被擠成直排。
  **原因**：固定寬度容不下多字。
  **修法**：改 `min-width` 加 `padding`。
- **症狀**：版面檢查腳本回「沒問題」，實機卻破版。
  **原因**：腳本量不到疊放、裁切與視覺密度。
  **修法**：667×325 一定截圖親眼看。
