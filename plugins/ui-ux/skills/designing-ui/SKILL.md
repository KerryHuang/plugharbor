# 設計畫面

動到使用者會看到的東西時使用。具體視覺風格、配色、字型的知識庫見 `ui-ux-pro-max` skill；本 skill 管「做新畫面時要守的通用規範與自查流程」。

## 0. 偵測受眾

先判斷這個畫面的使用者是誰，並在回報第一行寫「受眾：<名稱>」。

| 偵測到 | 附錄 |
|---|---|
| 使用者明確說兒童，或專案 README／設定標明兒童受眾 | `${CLAUDE_PLUGIN_ROOT}/references/audience-kids.md` |

- 一般專案不套兒童規範。
- 沒有對應附錄：照本 skill 的通用規範，加上專案既有畫面的寫法（先找 2–3 個同類畫面當樣板；有裝 workspace 就照 `workspace:convention-first`（可選））。做完問使用者要不要把這個受眾的規範整理成新附錄 `references/audience-<名稱>.md`，回報寫「受眾：一般」。
- 專案若有自己的 UI 規則（`.claude/rules/`、設計系統文件），優先於本 skill 的通用值。

## 核心原則

1. **一步一件事**：一個畫面只解決一個任務，主要動作最醒目，次要動作降級，不疊多層選單。
2. **每個動作都有回饋**：點了、送出了、失敗了，畫面上要有可見反應；長時間操作顯示進度。
3. **可以回頭**：除了流程起點，每個畫面都有明確返回路；返回與關閉的位置、符號全專案一致。
4. **狀態齊全**：載入中、空資料、錯誤、成功、停用，每個畫面都設計過，不只畫正常狀態。
5. **錯誤要能處理**：說清楚發生什麼、使用者下一步能做什麼；不責怪使用者；系統錯誤不擋住主流程。
6. **彈窗克制**：只在必須打斷時用；要做選擇的彈窗不能點遮罩關；看完就走的面板才可點遮罩關。
7. **一致**：同類元件只用一個實作與一套樣式（按鈕、彈窗、開關、提示條），不手刻第二份。
8. **可及性**：文字對比符合 WCAG AA（一般字 4.5:1）；點擊區夠大；不只靠顏色傳達資訊；可鍵盤操作（桌面／網頁）。
9. **素材**：不用別人的商標或受保護素材，新素材附授權檔。

## 文字

- 短標籤（按鈕、標題、名稱）一行放完，只有句子可以折行。
- 按鈕用動詞開頭、說明結果，不寫「確定」「OK」這類無資訊文字。
- 多語言：預留 30–40% 的長度；中英文都實際看過。

## 視覺與主題

- 顏色、間距、字級用變數或 token，不在元件內寫死。
- 每個主題（含暗色）都在最淺／最深的背景上量對比。
- 開關關掉、停用狀態用同一套樣式。
- 疊放元素不蓋字；裝飾避開文字。

## 響應式與版面

- 先決定支援的裝置與方向，列出最小與最大尺寸並全部跑過；最小尺寸親眼看截圖，程式檢查回「沒問題」不代表沒破版。
- 字級與尺寸用 `clamp()` 或相對單位；矮螢幕用 media query 另外處理。
- 一排並列的東西，寬度同時受寬與高限制，避免多一張卡就被切掉。
- 沒有被切掉、沒有重疊、沒有非預期的橫向捲動；橫向捲動的列要有捲動提示。
- 用腳本（python、sed）批次改 CSS 後一定看 `git diff`，巢狀 media query 之類的錯誤型別檢查抓不到。

## 失敗處理

- 儲存讀寫（localStorage、檔案、網路）都處理失敗路徑，失敗給使用者一條提示，流程照常。
- 讀到壞掉的資料先備份再回預設值，不直接吞掉。
- 等待外部事件（權限、網路、裝置）要有逾時和可以按的退路。
- 音效、動畫、非必要功能失敗不擋住流程。

## 做新畫面

複製這份清單，做完一項勾一項。做不到的（例如瀏覽器開不起來）在回報寫明哪一步、為什麼：

```
新畫面進度：
- [ ] 1. 偵測受眾；載入對應附錄（若有）
- [ ] 2. 找專案現成元件（彈窗、按鈕、返回、關閉、開關、提示條），照它的做法寫
- [ ] 3. 照核心原則寫，各種狀態（載入、空、錯誤、成功、停用）都做
- [ ] 4. 自動化測試：元件結構與主要互動流程
- [ ] 5. 實測：全部目標尺寸 × 各語言，最小尺寸截圖親眼看
- [ ] 6. 讀 ../auditing-ui/references/checklist.md（與受眾附錄的加項），和這次改動有關的條目逐條自查；沒過就回第 3 步
```

回報要說明第 6 步查了哪幾條、結果如何（沒過的寫原因）。沒說明就是還沒做完。
