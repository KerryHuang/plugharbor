# `.plugharbor/unattended.md` 範本

放在專案根，只在叫用 `unattended` 時讀，不佔常駐 context。每節都可以省略；省略的步驟照 SKILL.md 的預設做，沒有預設的就跳過並寫進回來報告。指令裡的路徑相對於專案根。

```markdown
# 無人值守：本專案設定

## 閘門
<指令>，例如 `bash <專案的閘門腳本> <worktree>`。
完整測試套件在本機跑還是交給 CI（交給 CI 就寫怎麼等結果）。
怎麼判斷通過（exit code、最後一行），以及注意事項（例如背景指令不要在結尾加 `echo "exit=$?"`，會讓背景工作永遠回 0）。

## 外洩掃描
<指令>；只印筆數不印字串。清單檔放 repo 外，寫明絕對路徑（新 session 不會知道在哪）。

## 授權 repo
只有這裡列的 repo 與操作能動；沒列的不動，寫進回來報告。每個 repo 一行：路徑或名稱、可做的操作（改／push／發版）、發版與採用的方式。
- 例：`<本專案>`：改、push、發版。
- 例：`<工具 repo>`：改、push；發版需使用者核准。採用新版的時機：單元邊界，切版後核對實際載入版本。

## 待辦檔
近期可開工項目的檔案路徑與所在區段（例如 `docs/todo.md` 的「近期可開工」）。每項欄位：目標與驗收、依賴、基準 SHA、預計路徑、資源、可暫停點、狀態、owner。沒有這份檔，空檔只從 roadmap 近期段的前置與審查留下的缺陷挑。

## 單元流程
覆寫 SKILL.md 第 2 節預設的地方，例如：什麼規模以上才另寫實作計畫、審查要幾個視角、本機要跑哪些測試類別、前端 typecheck／build 的指令、哪些變更一定要走兩次審查（安全、權限）。沒寫就用預設：設計夠細不另寫計畫、整段一次審查一次 CI。

## 插單預算
工作中發現的小錯可當場修的時間上限，預設 45 分鐘，計入測試、審查、CI、整合；超過後除權限洩漏、資料破壞、交付阻塞外轉入佇列。

## 合併
可不可以自己合併、推哪個分支、用 fast-forward 還是開 PR。自動駕駛模式要求這節寫明可以不經人核准自己合併（fast-forward，或開 PR 後自己 merge），否則不開。

## 部署
推哪個分支會部署、哪些路徑的變更才會觸發、怎麼等部署完成（指令或要看的頁面）。

## 實機驗證
怎麼登入（例如只用示範帳號按鈕，不輸入密碼）、要檢查什麼（版型寬度、主要流程），做完怎麼清理。

## 不並行的工作
- 會衝突的工作組合與原因，例如「兩件會加資料庫遷移的實作（遷移快照會衝突）」。
- 會互搶 CPU 的測試組合。
- 共用檔清單：平行的各條線都可能改到的檔案，例如 i18n 字串、路由、選單、DI 註冊、DbContext 與遷移。單元的計畫要列出會碰到哪幾個，碰到同一個就照順序做。

## 電源與睡眠
離開前要確認什麼（接電源、別蓋螢幕）、怎麼查睡眠紀錄。
```
