# `.plugharbor/unattended.md` 範本

放在專案根，只在叫用 `unattended` 時讀，不佔常駐 context。每節都可以省略；省略的步驟照 SKILL.md 的預設做，沒有預設的就跳過並寫進回來報告。指令裡的路徑相對於專案根。

```markdown
# 無人值守：本專案設定

## 閘門
<指令>，例如 `bash <專案的閘門腳本> <worktree>`。
完整測試套件在本機跑還是交給 CI（交給 CI 就寫怎麼等結果）。
怎麼判斷通過（exit code、最後一行），以及注意事項（例如背景指令不要在結尾加 `echo "exit=$?"`，會讓背景工作永遠回 0）。

## 外洩掃描
<指令>；只印筆數不印字串。清單檔放 repo 外，寫明絕對路徑（新 session 不會知道在哪）。

## 合併
可不可以自己合併、推哪個分支、用 fast-forward 還是開 PR。自動駕駛模式要求這節寫明可以不經人核准自己合併（fast-forward，或開 PR 後自己 merge），否則不開。

## 部署
推哪個分支會部署、哪些路徑的變更才會觸發、怎麼等部署完成（指令或要看的頁面）。

## 實機驗證
怎麼登入（例如只用示範帳號按鈕，不輸入密碼）、要檢查什麼（版型寬度、主要流程），做完怎麼清理。

## 不並行的工作
- 會衝突的工作組合與原因，例如「兩件會加資料庫遷移的實作（遷移快照會衝突）」。
- 會互搶 CPU 的測試組合。
- 共用檔清單：平行的兩條線都可能改到的檔案，例如 i18n 字串、路由、選單、DI 註冊、DbContext 與遷移。單元的計畫要列出會碰到哪幾個，碰到同一個就照順序做。

## 電源與睡眠
離開前要確認什麼（接電源、別蓋螢幕）、怎麼查睡眠紀錄。
```
