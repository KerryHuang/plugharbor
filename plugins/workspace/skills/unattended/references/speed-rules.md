# 速度規則：計畫、審查、測試、空檔、插單、工具 repo、CI、量測

SKILL.md 第 2 節流程的細則。專案設定（`project-config.md`）的同名欄位優先於本檔預設。

## 計畫與審查粒度

- **省計畫**（自動駕駛與無人值守的單元流程覆寫 `lifecycle:implement`「計畫與計畫審查不因改動小而省略」的預設）：設計文件已有介面、權限、錯誤行為、驗收案例，就不另寫實作計畫、不審計畫，整段交一個實作者做到底；缺哪項補哪項（補進設計，不另起計畫）。
- **每段一次審查**：整段完成後讀整份 diff 審一次、修一輪、一次 CI。這是正常路徑的目標，不是上限：安全、權限、資料錯誤、公開契約的問題必修，修完逐項核對原發現；審出 🔴 的安全類修完再審。
- **審查只從 diff 出發**：可讀必要上下文（呼叫端、權限守衛、既有測試），不跑測試；測試交 CI。
- **本機測試**：實作者只跑新增或修改的測試類別、直接受影響的既有類別、前端 typecheck／build；安全網（完整套件）交 CI。
- **修正交回原實作者**：續派沿用 context，附錯誤情境、通過條件、目前 SHA。同一問題反覆誤解就換人診斷；審查一律新 context。

## 空檔來源與重排

來源不限 roadmap：

1. 專案待辦檔的「近期可開工」區（位置寫在專案設定）。每項欄位：目標與驗收、依賴、基準 SHA、預計路徑、資源、可暫停點、狀態、owner。
2. roadmap 近期段的前置：行為決策題、驗收案例、file map。
3. 審查與報告留下的缺陷、flaky／CI 紀錄、測試耗時、文件落差。

規則：

- 依賴分階段：下一段的**實作**依賴這段，不代表它的決策題、驗收案例、file map 不能先做。只有依賴已滿足的項目能開工。
- 事件觸發重排：長工作丟背景、完成、失敗、資源釋放、使用者回答時各排一次。
- 帳本一行：`等待工作／SHA｜選定任務｜資源｜產出或暫停點`。選不到要寫具體阻塞，不反覆抄「下一段相依」。
- 寧可等的情況：窗口短於冷啟動與收尾成本、上游大幅變動、無授權、候選全部與進行中的工作衝突、機器飽和、主線即將需要接手。
- 小型唯讀整理主控自己做，不另派 agent。

## 線的配置

交付線固定兩條（主線一條、平行線一條，平行線沒有可開工項目就空著並記具體阻塞）；另有**工具線**，只在有工具或流程問題時開，修完即關。重測試仍經 `scripts/test-lock.sh` 排隊。

## 即時修正（插單規則）

工作中發現問題：先確認重現、影響範圍、最小修法，再依下表處置。

| 情況 | 處置 |
|---|---|
| 權限洩漏、資料破壞、卡住交付 | 立即打斷主線先修 |
| 其他小錯 | 佔用現有線當場修，獨立 commit |
| 要使用者決定 | 立刻問（使用者不在就照 SKILL.md 第 0 節分類記待確認） |
| 超時或冒出新決策 | 重新分類，禁止連環追修 |
| 大問題 | 進佇列，須有 owner 與啟動條件 |

- flaky 先查隔離、競爭、環境，不靠放寬斷言或重跑。
- 這取代「刻意沒做」作為預設處置；回來報告仍列出每項的處置結果。
- 授權範圍外的 repo 不適用本表，照「工具 repo」。

## 工具 repo

- 只能動專案設定「授權 repo」明列的 repo 與操作（改、push、發版）；沒列的不動，寫進報告。
- **發版與採用分開**：正在跑的單元用舊版，到單元邊界才切版；重大安全缺陷才暫停切換。
- 切版後核對實際載入的版本（例如叫用 skill 時顯示的路徑或版本）；`/reload-plugins` 不當作已更新的證據。
- 交接記錄（帳本、換新 session 的記帳）寫下 plugin 版本。

## CI 證據

- 最終版與已驗證版的測試與建置輸入相同（只差文件）可沿用該次 CI 結果。workflow、測試腳本、依賴、工具鏈有變動就不豁免。
- 首個失敗就通知診斷，不等其餘 job 跑完；但所有必要 job 通過才合併。

## 量測

試行三段，每段在帳本與累積報告記：交付時間、可避免的空等、返工、CI 重跑次數、token、提問數、變更規模（行數）、plugin 版本。三段後據此調整本檔。
