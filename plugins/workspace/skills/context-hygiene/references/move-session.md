# 把對話搬到另一個專案目錄

情境：對話是在 A 目錄開的，做的事卻一直屬於 B 專案；想讓它歸到 B，之後在 B 用 `/resume` 接著談。

## 先判斷要不要搬

- **只想從 B 接著談**：不必搬。在 B 執行 `claude --resume <sid>` 就能接回，`--resume` 照 id 找對話，不看目前在哪個目錄。接回後，新訊息仍寫進 A 的專案資料夾。
- **想讓它出現在 B 的 `/resume` 清單**：照下面三步搬。

## 三步

1. **先 `/exit`**，否則最後幾則訊息還沒寫進檔案。sid 會顯示在離開畫面上，或在 `/status` 查得到。
2. **原樣複製**：把 `~/.claude/projects/<A 的編碼>/<sid>.jsonl` 複製到 `~/.claude/projects/<B 的編碼>/`。同目錄若有同名資料夾 `<sid>/`（附屬檔，例如 subagents、tool-results），也整個複製過去。
   - 目錄編碼：絕對路徑中的 `/`、`.` 等字元都換成 `-`。例如 `/Users/me/Work/b` 的編碼是 `-Users-me-Work-b`。不確定的話，在 B 開一次 `claude`，看 `~/.claude/projects/` 下多出哪個資料夾。
   - A 的原檔留著當備份。B 已經有同名檔就停下，不覆蓋。
   - **不改檔案內容**：每行的 `cwd` 仍是 A 也沒關係，已實測過照樣會出現在 B 的清單。改寫對話紀錄還會被 auto mode 當成竄改擋下。
3. 執行 `cd B && claude --resume <sid>`。B 要先開過 Claude Code 並信任過。

## 記憶要判斷

auto-memory 依專案目錄分開存放，對話搬過去，記憶不會跟著走。逐條判斷：

- **只屬於 B 的**：從 A 的 `memory/` 搬到 B 的 `memory/`，兩邊的 `MEMORY.md` 都要更新；A 的索引留一行指向新位置。
- **通用的**（語言偏好、操作習慣）：兩邊各留一份；能放 user 層就放 user 層。
- 有進度類記憶的話，搬之前先補上「搬家當下的狀態與待辦」。

## 搬完的已知限制

- 對話開場載入的是 A 的 CLAUDE.md 與 rules，這些已經留在歷史裡；B 的設定要等之後的訊息才生效，需要時可以 `/compact`，或請 agent 重讀 B 的設定。
- 搬家前派出去的 worker（另一個 pane 或 session），回報時可能找不到這段對話；改看它的結果檔。
