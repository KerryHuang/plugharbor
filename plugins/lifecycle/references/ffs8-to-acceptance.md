# FFS §8 → 中性驗收案例格式

`lifecycle:qa-verify` 只吃中性驗收案例格式（欄位定義見 `lifecycle:qa-verify` 的 acceptance-format.md），不認 FFS 的章節結構。規格鏈完工後要驗收，**先照本檔把 FFS §8 轉成案例檔，再叫用 `lifecycle:qa-verify <案例檔>`**。`lifecycle:qa-verify --sweep` 的類別 4 同樣先轉檔。

轉檔由主 session 做（純文字整理，不開瀏覽器、不派 agent）。檔案放功能目錄的 `analysis/acceptance.md`；批次模式時放該輪 sweep 工作區。

## 欄位對照

FFS §8 每個子節（8.1 查詢、8.2 新增、8.3 編輯、8.4 刪除、8.5 例外）的表格，欄位為「編號｜驗收項目｜預期結果｜優先級｜對應 US」，一列 TC 轉一個案例：

| 案例欄位 | 來源 | 規則 |
|---|---|---|
| `id` | 編號欄 | 原樣照抄（`TC-C-002`），必須是 ASCII；全檔唯一 |
| `title` | 驗收項目欄 | 取操作前的那句話。驗收項目是整段操作（「填入… ，點擊儲存」）時，標題改寫成「在做什麼 → 結果類別」的短句（如「廠商未填被擋」） |
| `preconditions[]` | 驗收項目欄、§4／§5 的前置描述 | 驗收項目提到的既有資料或狀態（「已有單號 PO-001」「列表有 3 筆」）各拆一條；沒提就整欄省略。代號與資料值抄 FFS，不自己編 |
| `steps[]` | 驗收項目欄 | 以「，」「→」或編號切成一條一個動作，用畫面上看到的名稱（按鈕、欄位標籤）。驗收項目只是狀態描述（「資料載入」）時，補成開啟該畫面的一步 |
| `expected[]` | 預期結果欄 | 以「，」切成一條一個可觀察事實；訊息文字逐字保留（含標點與引號內容） |
| `channel` | 本表無此欄；看內容判斷 | 預期結果是畫面可見的 → 省略（視為 `ui`）；預期結果只有後端行為（只講 API 回應、資料庫狀態、Job）→ 標 `[api]`，qa-verify 會略過並列出 |

其他欄：

- 優先級、對應 US 不進案例。需要留痕就寫在案例檔的說明段落（會被忽略）。
- 預期結果裡「呼叫 POST API 成功」這類非畫面事實，從 `expected` 拿掉，只留畫面可見的部分（「顯示『新增成功』」「導回列表頁」）。整條都不是畫面事實才標 `[api]`。
- 預期結果仍是佔位符（`{初始欄位狀態}`、`{必填欄位}`）→ 不轉，列入轉檔回報的「規格未填」，由使用者決定先補規格或略過。
- 預期只有大意（「正確顯示現有資料」）→ 照大意寫進 `expected`；planner 不會替你補訊息文字，報告會標「無法比對」，這是規格該補的缺口。

## markdown 寫法

用 qa-verify 的 markdown 格式，案例標題行 `## <ASCII-ID> <標題> [通道]`，標題尾 `[通道]` 省略即 `ui`。區段名接受 `### 前置條件`、`### 步驟`、`### 預期結果`（同 `預期`）。一個子節對應一段，子節名放在 `#` 標題或說明段落即可（非案例行會被忽略）。

轉檔後的驗證交給 `lifecycle:qa-verify` Step 1：它會先跑 `validate.py acceptance`，非 `OK` 就把錯誤回給你（plugin 之間不共用 `${CLAUDE_PLUGIN_ROOT}`，本檔不寫跨 plugin 路徑）。常見錯誤：id 含全形字、案例缺 `步驟` 或 `預期結果`、`###` 區段名拼錯。

## 範例

假設 FFS §8.2 有這一列（虛構的「器材借用」功能）：

```markdown
| 編號 | 驗收項目 | 預期結果 | 優先級 | 對應 US |
| --- | --- | --- | --- | --- |
| TC-C-002 | 借用人欄未填，點擊儲存 | 借用人欄下方顯示「請選擇借用人」，表單不送出 | 高 | US-03 |
| TC-C-003 | 器材 EQ-001 已被借出時再次借用，點擊儲存 | 顯示「器材已被借出」，呼叫 POST API 回 409，列表筆數不變 | 高 | US-03 |
| TC-E-004 | 伺服器回 500 | 記錄錯誤日誌 | 中 | — |
```

轉成：

```markdown
# 器材借用 驗收案例

## TC-C-002 借用人未填被擋

### 步驟
1. 開啟器材借用頁，按「新增」
2. 借用人欄保持空白，按「儲存」

### 預期結果
- 借用人欄下方顯示「請選擇借用人」
- 表單不送出

## TC-C-003 重複借用被擋

### 前置條件
- 器材 EQ-001 已被借出

### 步驟
1. 開啟器材借用頁，按「新增」
2. 器材選 EQ-001，按「儲存」

### 預期結果
- 顯示「器材已被借出」
- 列表筆數不變

## TC-E-004 伺服器錯誤只記日誌 [api]

### 步驟
1. 讓伺服器回 500

### 預期結果
- 記錄錯誤日誌
```

轉換說明：

- TC-C-002 的「，」把驗收項目拆成兩步；預期的兩個畫面事實各一條。
- TC-C-003 把「器材 EQ-001 已被借出」抽成前置條件；預期裡的「呼叫 POST API 回 409」不是畫面事實，拿掉。
- TC-E-004 只有後端行為，標 `[api]`；qa-verify 目前只執行 `ui`，會略過並在回傳列出。
- 三個案例的 `id` 都是 FFS 編號原樣，報告與規格校正清單能直接用編號回到 FFS §8。

## 轉檔回報

轉完對使用者回報：案例數、`[api]` 案例數（會被略過）、規格未填而未轉的編號、預期只有大意的編號。再叫用 `lifecycle:qa-verify <案例檔>`。
