# 計畫審查

計畫存好、執行前跑一次（superpowers 路徑與退路都一樣）。審的是計畫，不是程式；實作後的 diff 審查交給 superpowers，退路只做自審。

## 誰審

依序挑第一個可用的（不因計畫小而跳級）：

1. `toolkit:agent-dispatch` 短問答（跨家族、唯讀）；提示以它的審查 prompt 範本為底，換成下面這份。
2. 同家全新 subagent（不能是寫計畫的 context）。
3. 都沒有 → 自審，結果標「自審」。

## 審查提示（自足，換掉 `<…>`）

```text
唯讀審查計畫（不改檔、不 commit、不派 subagent）。
對象：<計畫絕對路徑>；依據：<設計文件絕對路徑>。
重點找：
- 設計文件的每條驗收案例與決定，有沒有 task 負責；漏的列出。
- task 之間 Interfaces 的名稱與型別對不對得上。
- 有沒有 step 沒決定任何事（「處理邊界」「補測試」），或貼了整段程式碼。
- Review Focus 每條有沒有對應測試；Global Constraints 有沒有抄錯值。
- 最後一個 task 是不是 after.md。
輸出（繁中）只回 stdout：分「必修」「建議」，每條必修寫 task 編號、問題、具體反例；結尾「可開工／不可開工」。
```

## 結果

- reviewer 只回 stdout（唯讀，不放寬權限）；主控把回覆存成 `.tmp/implement/<feature>/plan-review-<n>.md`（不進 git）。
- 必修全修完才開工；建議由主控取捨並記一行理由。
- 必修 ≥ 3 → 修完再審一輪，只核對上一輪必修是否關閉、有沒有新引入的必修（定點核對）。
