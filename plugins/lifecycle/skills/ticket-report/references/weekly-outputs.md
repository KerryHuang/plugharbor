# 三份產出

三份產出的分工表與八段議程的分鐘配置在 weekly-flow.md 步驟 5。這裡只寫各章要放什麼。

## 三份互相指路的做法

報表抬頭放簡報檔名＋明細檔名；明細抬頭指回報表，並在開頭以目錄表標明「每張清單對應報表哪一節」。
三份的檔名／標題一律用**會議日**，對得起來。

## 各章內容

| 章節 | 要放什麼 |
|------|---------|
| 上週定調 | 一句話＋三個數字。**唯一要唸出來的段落** |
| 上次待辦兌現 | 對照上一份的「待辦事項彙整」，逐條標達成／未達，未達講原因不補交 |
| 各案進度 | 泳道圖，看每案卡在第幾棒 |
| 產能與時間 | 產能 vs 需求錯配、開發段 vs 驗收段耗時 |
| 卡點決策 | 每張卡＝現象（數據）／影響（誰被卡住）／選項 A-C／決策人＿期限＿ |
| 本週承諾 | 只押三件，每件標主責 |
| 臨時動議 | 預留議題（撈資料時發現、排不進議程的）＋現場登記空表 |
| 待辦事項彙整 | 來源／負責人／期限／完成四欄，最後一列留給臨時動議 |

已完成的事**貼著讓人看，不逐項唸**，一句話帶過。

## 敘事原則

- **主軸是客戶／案子，不是團隊**。主管問「某客戶什麼時候能收」，不是「後端做了幾張」。
- **名稱用功能名＋代碼**（「成品出庫作業（INV-050）」），報表正文不用票 ID。
- **卡點寫成決策卡**：現象（數據）／影響（誰被卡住）／選項（A/B/C）／決策人＿期限＿。
  只寫「積壓 264 項」沒人會動；給選項和空格才有人認領。
- **人力講配置不講考績**：報「哪一棒缺人」，不報「誰做幾張」。個人層級留給存檔版。

## 會議簡報（HTML）

report-writer 只寫草稿，HTML 由 `scripts/render_slides.py` 組出來：可點數字的筆數與抽屜清單都從 `dataset.json` 取，模型沒有機會寫錯或漏掉。骨架是 `drawer-template.html`（假資料，可直接開檔看效果）。

```markdown
# 週會簡報
> 週會日 2026-01-05

## 上週定調 [3]
上週**交付**偏少，主因見卡點決策。

@ 交付 {{delivered}}
@ 等驗收 {{review}}

## 各案進度 [5]
- 甲案等驗收 {{review}} 張
- {{review|成品出庫}} 卡在簽核

| 來源 | 負責人 | 期限 |
|---|---|---|
| 卡點 | 【人工填】 | 01-09 |
```

語法：`# ` 標題（必填）、`> ` 副標、`## 節名 [分鐘]`、`@ 標籤 {{資料集}}` 統計數字、`- ` 清單、`|` 表格、`**粗體**`。`{{資料集}}` 顯示該清單筆數；`{{資料集|文字}}` 顯示文字（不可含數字，代碼寫在按鈕外）。分鐘有寫就要加總 30，`dataset.json` 的每個資料集都要被引用至少一次；違反時腳本一次列出全部錯誤，不寫出簡報。

以下行為由腳本和骨架負責，不用寫進草稿：

版面骨架＝**議程的分鐘預算**：左側標尺標每節佔幾分鐘，加總 30。這個結構裝置編碼的是真實約束，不是裝飾。

**數字可點開**：每個統計數字是 `<button class="drill" data-k="...">`，點擊從底部滑出抽屜，列出 ID／標題／負責人／meta。
負責人取 `assignee`、連結取 `url`；沒有 `url` 就顯示純文字，不自己拼。
`priority`、`dueDate` 是選配欄：dataset 有才進 meta，沒有就不顯示該欄。
資料以 `<script id="drill-data" type="application/json">` 內嵌，**不要外部請求**（會議室可能沒網路）；內嵌 JSON 中的 `</` 要寫成 `<\/`。
抽屜內容一律用 `textContent` 寫入，票標題不當 HTML 解析。

頁面載入時自動比對每個按鈕顯示值與其清單長度，不符就把該數字標紅並在 title 提示。

其餘版面規範：單檔 self-contained、CSS inline、深淺色皆可讀、手機寬度不橫向捲動。

## 週報文件（Markdown）

用 ```mermaid 圖（GitHub、GitLab 原生支援）。四張：

1. **會議流程**：八段議程橫向串接，卡點標紅、臨時動議與待辦標綠
2. **全線存量**：需求池→待排→進行中→等驗收→完成，被擋的支線用虛線
3. **各案泳道**：`flowchart TB` ＋ 每案一個 `subgraph`（內含 `direction LR`），節點依狀態上色（綠完成／黃進行／灰未起）
4. **本週押三件事**：押注→預期效果

長條比較（產能錯配、耗時分桶）**用方塊字元表格**（`█████ 34`），不要用 mermaid 的 `xychart-beta`——版本支援不確定。

## 票務明細

開頭放 ticket-ops 回的「query 完整性」那一行（完整時也照抄；可能截斷時數字標下限），再放目錄表：清單名／項數／對應報表哪一節。
超大清單（進行中、等驗收、需求池）**不列**，改指向簡報的可點數字，並註明可在票務工具用階段篩選。

順手標出撈資料時發現的異常（重複票、逾期數月未動的高影響票），放在對應清單後面當備註——那是 PM 會想知道但沒人會主動報的東西。
