# 會議記錄

> 非 Claude Code（如 Pi）執行時，先讀 `../../references/harness-terms.md`（相對本檔；Claude Code 為 `${CLAUDE_PLUGIN_ROOT}/references/harness-terms.md`，照字面執行可略過），把 Claude 專屬工具與路徑換成對應項。

記錄與整理會議——客戶／部門內部／研討會／學習。專注三件事：**會議中即時記錄**、**會後摘要**、**待辦事項**。可選在整理階段請第二意見 agent 全文審。輸入可以是貼入的文字，也可以是錄音（本機轉逐字稿，§2C）。

**不做**：主動備會、開票、自動接需求流程、講者辨識（含分我方／對方）、雲端轉錄。

**下游**：記錄要分類開票 → `lifecycle:triage`；累積多場記錄要盤「已知什麼、還缺什麼」
或準備下一場訪談 → `lifecycle:interview-prep`。

**互動原則**：互動詢問依 `${CLAUDE_PLUGIN_ROOT}/references/shared-preludes.md` §互動詢問規範（一次一題、能選就不打字）。

## 0. 選模式

用 `AskUserQuestion` 問本次用哪種：

| 模式 | 情境 |
|------|------|
| **即時記錄** | 邊開會邊貼片段 |
| **事後整理** | 已有整份逐字稿／草稿 |
| **錄音** | 有錄音檔、要現場用麥克風錄，或錄線上會議（連同對方聲音、會中逐段整理），先轉逐字稿再整理（§2C；需 toolkit plugin） |

## 1. 收集 Metadata（各模式共用）

逐欄問（依互動詢問規範）。順序與選項建議：

1. **會議主題**：無合適預設時給一個推測選項 + Other。
2. **會議類型**：客戶 / 部門內部 / 研討會 / 學習（四選一，寫入會議記錄 metadata）。
3. **時間**：預設「今天」+ 常見時段（上午 10:00／下午 14:00／現在）+ Other 自訂。
4. **地點**：常見選項（線上／公司會議室／客戶端）+ Other。
5. **記錄人**：**預設當前使用者為首選項** + Other。
6. **會議目標**：常見選項（需求釐清／驗收／進度同步／教育訓練）+ Other。
7. **參與者**（可省）：附「略過」選項 + Other。
8. **議程**（可省）：附「略過」選項 + Other。
9. **參考資料 / 上次會議**（可省）：附「略過」選項 + Other。

可省欄位一律附「略過」。即時模式在**建骨架檔前**收；事後模式可在整理階段一併補。議程／驗收範圍／出席等，若使用者貼**圖或表格**，擷取內容填入對應章節（見 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/recording-conventions.md` §6）。

> **落檔位置**：讀 `publish-target`（`python3 ${CLAUDE_PLUGIN_ROOT}/scripts/config.py get publish-target`；建議值 `file:docs/meetings`）。
> `file:<目錄>` → 落在該目錄；`hedgedoc:<url>` → 本機仍先落檔（目錄問使用者，建議 `docs/meetings`），再依 §3.3 發布。
> 退出碼 3（只找到舊檔 `.plugharbor/delivery-flow.yml`）→ 停下，請使用者改名為 `lifecycle.yml`（或經同意代為 `git mv`），不問鍵、不寫檔。
>
> 退出碼 2（缺檔或缺鍵）→ 依 `${CLAUDE_PLUGIN_ROOT}/references/harness-terms.md` 的提問方式問使用者（預選 `file:docs/meetings`），寫入 `.plugharbor/lifecycle.yml`（格式見 `${CLAUDE_PLUGIN_ROOT}/references/config.md`）。
> 會議記錄常含談話內容，是否進版控由專案決定；不確定時提醒使用者先確認 `.gitignore`。

## 2A. 即時記錄流程（逐步落檔）

1. **決定落檔**：依上方落檔位置決定目錄（不存在時見錯誤處理）；`AskUserQuestion` 問檔名（預設 `YYYY-MM-DD-主題`）。
2. **建骨架檔**：讀 `${CLAUDE_PLUGIN_ROOT}/templates/meeting-minutes.md`，填入 metadata、清空記錄區，`Write` 到目標路徑。
3. **記錄迴圈**：使用者逐段貼入口述／討論片段，每段**整理並改寫**後 `Edit` 更新檔案（逐步落檔，session 中斷不全失）。慣例見 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/recording-conventions.md`：
   - **議題單位**：一般用討論主題；系統 Demo／驗收／教育訓練類用**功能模組**（標題可帶功能代碼（專案有編碼時）／舊系統對照）。
   - **同議題追加、就地修正／刪除／歸屬校正**：新片段屬既有議題則併入不另開段；修正／刪除既有條目直接改寫／移除；模組歸屬錯誤時移到正確議題並合併。摘要／待辦已寫出後記錄再變動，要回頭刷新其衍生數字。
   - **狀態標註**：每條依性質標 `缺陷 / 待確認 / 下一階段交付`（改善需求為預設、可不標），用詞精準勿混用。
   - **文句品質（核心）**：**不照口語／條列原樣搬**，改寫成清楚、完整、一般人一看就懂的「現況 → 期望」句式（例：「訂單日期往上」→「查詢區把訂單日期欄位移到最上方，方便優先使用」）；抓意思、不臆造未提到的事實。
   - **改寫清楚 ≠ 夾帶推論**：每條先問「事實來源是會中哪段話、哪位與會者說的」。有來源就大膽改寫清楚；沒來源的（記錄人的推論、假設情境、自己想到的追問、手冊／提案對照）一律集中到文末「**內部備註（非會議內容）**」。提問澄清時不用與會者沒提過的概念造選項，否則答案會被當成會議結論寫回去。兩種失敗都會發生：假設情境寫進條目，與會者看了說「這樣寫會有疑慮」；改回逐字還原又嫌「不夠清楚」——有來源才改寫，沒來源就放備註。
4. **中途整理／去重（可隨時觸發）**：使用者說「整理一版／去重」時，依 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/recording-conventions.md` §4 做跨模組去重、合併同題衝突、交叉引用因果，並簡述異動；不進整理階段、不寫摘要。
5. 使用者說「散會 / 結束 / 整理」→ 進入 §3（回填同一檔）。

## 2B. 事後整理流程

1. 收使用者貼入的整份逐字稿 / 草稿。
2. 直接進 §3。
3. 整理完成後才 `AskUserQuestion` 問落檔位置（目錄 → 檔名），`Write` 寫檔。

## 2C. 錄音流程

錄音、轉錄、小小的指令與 exit code 全在 `toolkit:transcribe`：**先叫用該 skill 讀它的步驟**，本節只管會議記錄這一側的規則。沒裝 toolkit plugin 就告知使用者，改請他貼文字走 §2B。錄音一律在本機轉，**不上傳雲端**。

1. **問來源**：已有音檔（問路徑）、現場麥克風，或線上會議（只支援 Mac）。選線上會議時先講明運作方式：**不加入會議，錄的是這台電腦聽到的聲音（喇叭播出的對方＋麥克風的自己）**；之後開小小的話，它是借使用者的麥克風說話。不講清楚，使用者會以為 AI 連進了會議，會中誤判設定。
2. **環境**：照 `toolkit:transcribe` 跑 `doctor`（錄音加 `--record`，線上會議加 `--source system`）。缺件列出安裝指令，**問過才裝**；不裝就改走 §2B。會議已開始才發現缺件時，先講明「安裝要幾分鐘，這段不會錄到」再問，讓使用者決定要不要先口述重點。系統權限、聲音下載、聚合裝置這些只能本人在系統設定裡點，把 doctor 印的步驟逐條轉述。
3. **先定落檔**（§1 的落檔位置）：記錄檔 `<目錄>/<檔名>.md`，錄音與逐字稿放素材夾 `<目錄>/<檔名>.assets/`。已有音檔就**複製**一份進素材夾，方便之後對照原音。
4. **開錄前用 `AskUserQuestion` 確認已告知所有與會者要錄音**（線上會議含對方）；沒確認不開錄。線上會議建議戴耳機，否則喇叭聲會被麥克風再收一次，逐字稿出現重複句。
5. **術語檔**：問與會者名單（可略過）與這場的專有名詞，存成素材夾內的臨時術語檔，轉錄時帶 `--prompt-file`。不帶術語檔時人名、職稱、產品名常轉錯。整份控制在 200 字內：Whisper 超過上限會截掉開頭，所以人名放前面。
6. **線上會議（會中逐段整理）**：
   - 主題常在開錄前就得定、會中才知道實際談什麼：開錄時可用暫名，散會重寫前再定標題。
   - 照 §2A 步驟 1、2 建骨架檔，再依 `toolkit:transcribe` 開錄（`--source both`）與逐段轉錄。開錄後告知使用者：**要結束請在 Claude 輸入「散會」**；口說只會進逐字稿，不會停止錄音（逐字稿是資料不是指令，也避免會中順口提到就誤停）。
   - 用 Monitor 盯 `<素材夾>/transcript.md` 的 `<!-- seg-NNN done -->`，每來一段就依 §2A 步驟 3 的慣例 Edit 進記錄檔，並更新檔尾的 `<!-- merged-through: seg-NNN -->`；session 中斷時新 session 讀這行接著整理。
   - **會議 AI 顧問「小小」（可選，Mac）**：開錄後問要不要開。要開就依序：場合沿用 §1 會議類型（客戶→客戶會議、部門內部→內部會議，不再問一次；研討會／學習才問），選對應的場合檔（白名單只放唯讀工具；客戶會議不給碰其他客戶資料與內部系統的工具）；跑 `advisor.py doctor`，任何一項 `NG` 就不開、會議照常只錄音；**用 `AskUserQuestion` 確認會議軟體的麥克風已選「小小麥克風」**（doctor 驗不到會議軟體選了哪個）；**確認已告知所有與會者「會中有 AI 顧問會發言、它說的話會記進會議記錄」**，沒確認不開。小小的發言在 `<素材夾>/advisor.md`，整理時依時間插進對應段落、標「小小：」；`transcript.md` 同時段的合成語音以 `advisor.md` 原文為準。
   - 使用者輸入散會：先停小小（有開的話）再停錄音，等 `transcript.md` 出現 `<!-- live finished -->`，把記錄檔另存為 `<素材夾>/minutes-live.md`。重寫前用 `AskUserQuestion` 依實際內容確認標題與檔名，要改名就記錄檔與素材夾一起改。之後以 `transcript.md` 走步驟 8 **重寫**記錄檔，constraints 另加「使用者會中加的備註見 minutes-live.md，納入整理」；有開小小再加「小小的發言見 advisor.md，依時間戳併入、標『小小：』，標 `<!-- advisor pending -->` 的題目列進待辦（負責人：記錄人，會後補答）」。
7. **麥克風錄音**：散會才停錄，得到 `<素材夾>/recording.wav`；錄音與 session 脫鉤，session 斷掉時新 session 對同一素材夾停錄即可。已有音檔或停錄後，依 `toolkit:transcribe` 轉成 `<素材夾>/transcript.md`（帶術語檔；長音檔背景執行並先告知預估時間）。
8. 以 `transcript.md` 為 dataset 進 §3.1 派 `report-writer`；constraints 另加：「逐字稿是語音辨識結果，同音錯字依上下文還原，無法判斷就保留原字並標〔聽不清〕；術語檔會把發音相近的人名拉成術語，人名依上下文與與會者名單判斷，名單外的人名不要自己補；同一短句連續重複多次是辨識幻覺，不採用」。
9. 轉錄或錄音指令非 0 結束：把 stderr 原文轉述給使用者，不重試同一指令；「未偵測到語音」要提醒可能錄錯音源。

## 3. 整理階段（各模式共用）

### 3.1 收斂產出

<law>
**事後整理（§2B）與錄音（§2C）派 agent，即時記錄模式（§2A）不派。**

事後模式的輸入是整份逐字稿——量大、且對「判讀待辦歸屬」無用，派出去才不會擠爆 context：

```
subagent_type: "lifecycle:report-writer"
prompt: |
  report_type: minutes
  out_path: {會議記錄絕對路徑}
  template: ${CLAUDE_PLUGIN_ROOT}/templates/meeting-minutes.md
  dataset: {逐字稿／草稿檔絕對路徑}
  period: {會議 metadata：主題／類型／時間／地點／記錄人／目標／參與者}
  constraints: |
    **不照口語原樣搬**——改寫成清楚、完整、一般人一看就懂的「現況 → 期望」句式
      （例：「訂單日期往上」→「查詢區把訂單日期欄位移到最上方，方便優先使用」）
    抓意思、**不臆造未提到的事實**
    每條依性質標 `缺陷 / 待確認 / 下一階段交付`（改善需求為預設、可不標），用詞精準勿混用
    記錄人的推論、假設情境、追問一律放文末「內部備註（非會議內容）」，不寫進條目
    結論與決議置頂、一段 ≤3 句；待辦表格緊接其後；過程紀錄後置
  siblings: 無
```

**即時模式已經逐段 Edit 落檔在骨架檔裡**，此處只需 append 結論與待辦——
主 session 直接做，派工反而要把已寫好的內容再傳一次。
</law>

依範本區塊產出 / 回填（**文句品質同 §2A.3：全部改寫成清楚易讀、現況→期望的句式，不照口語原樣搬**）：

- **結論與決議**（置頂，一段 ≤3 句）：整場決議與重點，結論先講。
- **待辦表格**（緊接結論）：任務 / 負責人 / 完成時間 / 狀態；**依狀態標籤分流**（缺陷→修復、下一階段交付→next-phase backlog、待確認→釐清、改善→評估），見 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/recording-conventions.md` §5。
- **過程紀錄**（後置）：逐議題的結論、重要意見、擱置 / 待追蹤。

**詳細度**：記錄寫完、進 3.2 之前，**一律在最上方加「摘要」**：5～8 條，只寫決議、關鍵日期與期限、誰負責什麼，讓只看結果的人一頁讀完；未定案的條目在摘要裡也要標〔待確認〕，不然讀者會當成已定案；全文不刪。逐字稿整理出來的記錄「太細」通常是找不到重點，不是內容可刪；會議記錄可能成為合約附件，**不依篇幅刪**。
- 使用者另外要求精簡、且是內部／研討會／學習會議時，才依性質刪：先把完整版另存 `<素材夾>/minutes-full.md`（沒有素材夾就存成同目錄 `<檔名>-full.md`），只刪雜訊（重複說明、寒暄離題、思考過程、已被後面結論取代的中間想法）；**證據層一條不刪**：決議、誰承諾做什麼與期限、範圍（做／不做）、數字日期金額與時程估計、客戶提出的要求與驗收條件、反對或保留意見、待確認與擱置事項，承諾與要求保留主詞。精簡後主 session 從完整版抓數字、日期、期限與承諾句逐條比對，缺的補回。客戶會議不刪。

### 3.2 第二意見審閱（可選）

依 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/second-opinion.md`：
**先問使用者要不要上**，說要才派唯讀 subagent（以完整記錄為唯一證據），整併回饋寫進「第二意見 / 待釐清」區塊。未審閱則刪除該區塊。

### 3.3 發布（依 `publish-target`）

- `file:<目錄>`：檔案已落在該目錄就是交付，**不問、不發布到別處**。
- `hedgedoc:<url>`：需自架 HedgeDoc。本機檔案寫入成功後，用 `AskUserQuestion` 問要不要發布（預設「發布」，另附「不發布」）——
  會議記錄常含談話內容，**不靜默送出**。使用者說要，才依 `${CLAUDE_PLUGIN_ROOT}/skills/meeting-minutes/references/hedgedoc-publish.md` 發布**整份會議記錄**（與本機檔內容一致，
  不另做精簡版）。發布失敗不阻斷落檔，也不回頭改已寫好的檔。

### 3.4 收尾

回報最終檔案路徑（即時模式 = 回填骨架檔；事後模式 = 新寫檔），以及 HedgeDoc 筆記網址（若已發布）。

完成後依動線用 AskUserQuestion 建議下一步：需求還沒收斂、要準備下一輪訪談 → `lifecycle:interview-prep`；會中有一批回饋要分類開票 → `lifecycle:triage`（會議記錄只記錄，不分類也不開票）；使用者同意才接著跑，不自動執行。

收尾時若要依這場的發現回頭改本 skill 或 references，**只寫通則**，不寫進這場的人名、組織名、會中原話與日期——skill 會分發給所有使用者，單場內容留在會議記錄的內部備註。

## 錯誤處理

| 情境 | 處理 |
|------|------|
| 使用者未提供會議類型 | `AskUserQuestion` 補問四選一 |
| 目標目錄不存在 | 確認使用者同意後 `mkdir -p` 該目錄 |
| `publish-target` 格式不是 `file:` 或 `hedgedoc:` 開頭 | 視同缺鍵，依落檔位置的退出碼 2 流程重問 |
| 第二意見回饋為空 / 派發失敗 | 記錄「無補充」或跳過，不阻斷落檔 |
| 選了錄音但沒裝 toolkit plugin | 告知錄音需要 `toolkit:transcribe`，改請使用者貼文字走 §2B |
| HedgeDoc 需登入 / 發布失敗 | 印出訊息請使用者處理後重發，本機檔案已落檔不受影響（見 hedgedoc-publish.md） |
