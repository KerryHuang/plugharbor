# 第二意見審閱（meeting-minutes 整理階段）

於整理階段「收斂產出」之後觸發。**先問使用者要不要上，說要才派。**
審閱 agent 唯讀，只回饋建議；主 session 負責整併落檔。

## 1. 詢問（一定先問）

用 `AskUserQuestion` 問一題：

> 這場要不要請第二意見 agent 審一遍會議記錄？

選項：
- 要，請 agent 審
- 不用（預設）

回答「不用」→ 跳過本流程，直接回報檔案路徑。

## 2. 派發（回答「要」才做）

派一個唯讀 subagent（`general-purpose`；環境若有領域顧問類 agent 可改用，需先確認它是唯讀），以**完整會議記錄**為 context。
**以會議記錄內容本身為唯一證據來源**，明寫在 prompt。

```
context: |
  {完整會議記錄 markdown 內容}
審查重點：指出隱含需求、邊界問題、資料來源與狀態流轉的疑點、待釐清清點。
  以會議記錄為唯一證據來源，勿臆測記錄外事實；不改檔。
```

## 3. 整併落檔

主 session 收回饋，整併寫進記錄檔「第二意見 / 待釐清」區塊：

- **隱含需求**：條列。
- **邊界 / 待釐清**：條列，每條簡述理由。
- **建議後續**：若 agent 建議接需求流程，**只列建議、不自動交棒**。

審閱 agent 不落檔；整併與寫檔一律由主 session 執行。這個區塊屬於「審閱意見」，
與「內部備註（非會議內容）」一樣，都不混進會議條目。
