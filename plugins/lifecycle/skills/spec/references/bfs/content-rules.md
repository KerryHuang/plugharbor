# BFS 內容撰寫規範

## 禁止項

- **禁止程式碼**：不包含任何程式語言框架程式碼
- **禁止指定實作技術**：不寫死 framework 名稱、ORM、library、設計模式、類別命名；SAD 帶入的技術建議須改寫為「**建議方案**」並加註「實作以 RD 決定為準」

## 允許內容

- Mermaid 圖（`flowchart`、`erDiagram`、`stateDiagram-v2`）。ER 圖**不使用** `PK_FK` 複合角色
- JSON 範例（使用擬真資料，避免佔位符）
- 檔案結構樹
- 虛擬碼（旁加註「示意，非實作」）

## API 端點完整性

每個端點**必須**包含：
- HTTP 方法 + 路由
- **成功 HTTP 狀態碼**（POST=201+`Location`、PUT=200、DELETE=204、BATCH=207；依 `naming-conventions.md`「API 端點標準」）
- Request / Response 模型表格（PascalCase）
- 成功 JSON 範例（camelCase）
- 錯誤回應說明
- 批量端點另須定義「部分成功」行為（207 逐項 或 整批交易），不可留白

## 副作用

若操作需觸發副作用（審計日誌、通知），規格書應明確定義觸發條件和目標。

## 功能類型對應章節

| 功能類型 | 必填章節 | 選填章節 |
|---------|---------|---------|
| CRUD API | 1-6, 8-15 | 7（排程） |
| 排程同步 | 1-3, 7, 9-15 | 4-6（可簡化） |
| **報表/查詢型** | 1-6（**§6.0 DoR 必填**）, 8-15 | 7（排程） |
| 混合類型 | 1-15 | - |

> **報表/查詢型**：端點回傳集合 / 有篩選排序 / 提供匯出 / 含統計。§6.0 列表/報表端點規格基準（分頁/排序/日期邊界/1:N 取值/聚合母體/匯出/權限/效能）**強制**，依 `list-endpoint-dor.md`。
