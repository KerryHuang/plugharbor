# 邊界與例外路徑分析指南（SA 用）

> SA 在三流分析（Step 4-6）後執行。系統性盤點 FRD 業務層「例外情境」未涵蓋的**系統層邊界**，輸出邊界清單供 BFS（§7 驗證 / §8 例外 / §8.4 並發）與 FFS 承接。

## 為什麼是 SA 的責任

FRD 描述業務正常流程與少數例外；SA 必須補齊系統層的邊界與失敗路徑，否則 BFS / FFS 各自臆測，導致並發、狀態、資料一致性漏洞。**邊界不是 PM 想得到的，是 SA 從系統角度推出來的。**

## 維度清單

逐一檢視 `${CLAUDE_PLUGIN_ROOT}/references/boundary-dimensions.md` 的 **B1–B10 通用維度**與 **M1–M4 領域特有維度**。
該檔是唯一維度定義權威，`dev-readiness` 事後驗證用的是**同一份、同一組編號**——
SA 盤點時漏掉的維度，正是 dev-readiness 會退回來的缺口。

- **B11／B12 本階段不適用**：畫面內容規格與輸出管道要等 FFS 存在後才驗。
- **B13 本階段適用**：SAD 訂下的格式／長度／閾值，凡有設定檔或 schema 落點者，
  盤點結論要**寫成「自 {來源} 推導」而非字面值**——下游 BFS／FFS 會照抄 SAD 的寫法，
  這裡寫死，整條鏈就跟著寫死。
- 每個維度都要有結論，**標「不適用」也是結論**；留白代表沒盤點過。

## 輸出格式（寫入 SAD §6.6）

| 邊界類型 | 維度 | 情境 | 預期系統行為 | 下游落點 |
|---------|------|------|------------|---------|
| 資料 | B1/B2/B3 | {空 / 極值 / 重複} | {回應 / 阻擋訊息} | BFS §7 VR、FFS §4 |
| 狀態 | B4 | {非法轉換} | {阻擋 + 訊息} | SAD §2.3、BFS §2.4 |
| 並發 | B5 | {同時編輯} | {HTTP 409 / 鎖策略} | BFS §8.4 |
| 主從 | B6 | {明細增刪後表頭重算 / 級聯刪除} | {何時算、由誰算 / 連鎖或擋下} | BFS §8.3、FFS §5.2 |
| 權限 | B7 | {越權存取} | {HTTP 403} | BFS §8 |
| 一致性 | B8 | {交易 / 外部失敗 / 部分成功} | {rollback / 補償 / 降級} | BFS §8.3 |
| 既有資料 | B9 | {歷史髒資料 / 必填回填} | {顯示 / 阻擋 / 回填策略} | SAD §4.4、BFS §7 |
| 排序 | B10 | {排序鍵非唯一 / 可為空 / 字串編號} | {決勝欄 / NULL 位置 / 序語意} | BFS §6.0、FFS §2 |

**狀態完整性**：同時更新 SAD §2.3 狀態流轉，補上非法轉換與並發衝突，而非只畫正常路徑。

> 📎 業務層的例外情境（單一 US 的 Given-When-Then 例外）見 FRD §2；本分析只補 FRD 未涵蓋的**系統層**邊界，不重抄業務例外。
