# 驗證細節

`build` 結束時自動跑 `verify`；也可單獨 `node "$ENGINE/demo-video.mjs" verify <out>`。任何一項失敗，exit code 非 0。

## 引擎會做的

| 項目 | 做法 | 失敗條件 |
|---|---|---|
| 影像軌長度 | `ffprobe stream=duration`（video 軌） | 與預期總長差超過 0.2 秒，或讀不到 |
| 音軌長度 | 同上（audio 軌） | 同上，或與影像軌差超過 0.2 秒 |
| 每段旁白有聲音 | 對 `timeline.json` 每段的時間區間跑 `ffmpeg -af volumedetect` | 區間內最大音量低於 −50 dB |
| contact sheet | 開頭、每段中點、結尾各取一格，3 欄拼成 `verify/contact.jpg` | —（供人看） |

**容器長度不是證據**：容器取最長那條軌，影像軌提早結束時容器仍是全長。

## agent 要自己做的

用 Read 開 `out/verify/contact.jpg`，逐格對照旁白稿，回報：

- 每格畫面是不是該段旁白在講的操作（有沒有停在錯的頁面、報錯畫面、空白）。
- 字幕有沒有蓋到該段示範的重點 UI。
- 有沒有出現不該出現的資料（真實姓名、客戶名稱、內部網址）。

## 回報格式

四項各自宣稱，沒做到的標「未驗證」：

```
影像軌／音軌長度：通過（影像 21.4s／音軌 21.4s）
每段有聲音：通過（4 段 max 音量 −4 dB 上下）
畫面內容：已開 contact sheet 逐格看過，<結論>
語音品質／發音／字幕對齊：未驗證，待使用者試聽
狀態：⏳ 等使用者試聽
```
