# 中性驗收案例格式

`qa-verify` 的輸入。與規格文件的章節結構無關：任何來源（人寫的驗收清單、其他 skill 轉出的案例）只要整理成這個格式就能驗。markdown 與 YAML 皆可，語意相同。

## 欄位

| 欄位 | 必填 | 說明 |
|------|:----:|------|
| `id` | ✓ | 案例 ID，全檔唯一（如 `AC-1`）；會成為 plan 的 case id，報告以它定位 |
| `title` | ✓ | 一句話說這案驗什麼 |
| `preconditions[]` | | 前置條件，一條一句；需要既有資料或特定狀態才寫，無則整欄省略 |
| `steps[]` | ✓ | 操作步驟，一條一個動作；用使用者在畫面上看到的名稱 |
| `expected[]` | ✓ | 預期結果，一條一個可觀察事實：畫面訊息原文、欄位狀態、列數等 |
| `channel` | | 通道標記，如 `ui`、`api`；省略視為 `ui`。目前只執行 `ui`，其他通道的案例會被 planner 略過並在回傳列出 |

寫法原則：

- `expected` 只寫畫面上看得到的事實，訊息要逐字（含標點）。只知道大意就寫大意，planner 不會替你補訊息文字。
- 一案綁多條規則（必填、長度、不可重複）時拆成多案，一案驗一件事。
- 不寫判斷句（「與修改前相同」），寫要讀的值。

## markdown 寫法

`## <id> <標題> [通道]` 起一案；`### 前置條件`、`### 步驟`、`### 預期` 後接清單項。標題尾的 `[通道]` 可省略。其餘文字（含 `#` 一級標題、說明段落）被忽略。

```markdown
# 分類維護

## AC-1 代碼重複被擋 [ui]

### 前置條件
- 已存在代碼 A01

### 步驟
1. 開啟分類維護頁，按「新增」
2. 代碼填 A01，按「儲存」

### 預期
- 顯示「代碼重複」
- 清單列數不變
```

最小案例（無前置條件）：

```markdown
## AC-2 新增表單可開啟

### 步驟
1. 按「新增」

### 預期
- 出現空白表單
```

markdown 解析的限制：

- 只認 ASCII 的 id（`AC-1`、`TC_01`）；`## AC-1：標題` 的全形冒號可用。其他 `## ` 行（如 `## 說明`）結束目前案例，其下內容不屬於任何案例。
- 只有 id 沒有標題會報錯（`title` 必填），不會被略過。
- `### ` 區段名只認 `前置條件`、`前置`、`步驟`、`預期`、`預期結果`（或英文 `preconditions`、`steps`、`expected`）；其他名稱報「未知區段」。
- 巢狀清單攤平成同層；清單項下的續行（縮排說明）被丟棄；標題尾端的 `[...]` 一律當通道（轉小寫）。
- ``` 圍欄內的行忽略；檔案可帶 BOM。

## YAML 寫法

```yaml
cases:
  - id: AC-1
    title: 代碼重複被擋
    channel: ui
    preconditions:
      - 已存在代碼 A01
    steps:
      - 開啟分類維護頁，按「新增」
      - 代碼填 A01，按「儲存」
    expected:
      - 顯示「代碼重複」
      - 清單列數不變
```

## 驗證

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/skills/qa-verify/scripts/validate.py acceptance <案例檔>   # .md 走 markdown，其餘當 YAML
```

空檔、零個案例、缺 `steps`／`expected`、id 重複、未知鍵都會失敗。通過印 `OK`。

## 與 plan 的關係

planner 逐案產 plan 的 case：`id` 沿用、`來源.章節` 填案例 id、`步驟`／`預期` 由 `steps`／`expected` 轉成 `step-dsl.md` 的步驟與預期槽（需開實機對欄名）、`前置資料` 由 `preconditions` 轉成條件句。其他來源要接進 `qa-verify`，轉成本格式即可，不必知道 plan 的格式。
