# 規格 §2.3 → 驗收案例檔

輸入是 `lifecycle:spec` 產的規格（`<spec.dir>/<feature>.md`）時，先照本檔轉成案例檔，再走 Step 1 的案例檔模式。轉檔由主 session 做（純文字整理，不開瀏覽器、不派 agent）。

## 規則

1. **原樣轉**：§2.3 每條 `#### <id> <標題> [通道]` 升兩級成 `## <id> <標題> [通道]`，`##### 前置條件`／`##### 步驟`／`##### 預期` 升成 `###`；清單項照抄，不改寫、不補字。格式定義見 `acceptance-format.md`。
2. **缺欄就停**：任一案缺 `步驟` 或 `預期`、id 不是 ASCII、預期仍是佔位符（`{…}`）→ 不轉，列出「案例 id：缺什麼」交使用者補規格（`lifecycle:spec --change`），不猜。
3. **落檔**：寫到 `<ws>/.tmp/qa/<feature>.md`（`<feature>` 為規格檔名去掉 `.md`），再以該路徑進 Step 1 的 `validate.py acceptance`；Step 1 的工作區因此以功能命名，不同功能互不覆蓋。

## §2.3 不是案例格式

舊規格或其他來源的設計文件（例：只有 `- [ ] AC-01：給定…當…則…` 的清單，或根本沒有驗收一節）：

- 有 Given／When／Then 句子 → 擬成案例草稿（給定 → 前置條件，當 → 步驟，則 → 預期），落同一路徑，**先給使用者確認**再跑。
- 完全沒有驗收內容 → 從內文擬草稿並標「擬稿、未經確認」，同樣先確認；使用者不確認就停。

## 範例

規格裡：

```markdown
#### AC-02 備註超過 200 字被擋 [ui]
##### 步驟
1. 開啟 SO-001，備註填 201 個字，按「儲存」
##### 預期
- 顯示「備註不可超過 200 字」
```

轉成：

```markdown
## AC-02 備註超過 200 字被擋 [ui]
### 步驟
1. 開啟 SO-001，備註填 201 個字，按「儲存」
### 預期
- 顯示「備註不可超過 200 字」
```
