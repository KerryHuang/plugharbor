# 列表／報表端點 開發就緒度（DoR）

> 通用規範，**不綁特定專案的值**。目的：讓「清單/報表型」端點的規格，開發者能直接上手，不必停下來猜或回頭問。

## 適用範圍

任何端點符合下列任一條件即適用：
- 回傳集合（array / list / 分頁）
- 有篩選 / 排序 / 日期區間參數
- 提供匯出（Excel / CSV）
- 含統計 / 小計 / 計數

## 核心原則：先慣例、後自定義、禁 hand-wave

每個維度**二擇一**解析，不可留模糊結案：

- **引用既有慣例** → 附 codebase 證據路徑（探索出的專案基底/工具），規格只說「遵循 X」。
- **本功能自定義** → 寫出明確值（欄位、邊界、公式）。

❌ 禁止：「比照既有 Handler」「反查回填」「對齊報表」「依需要分頁」這類把責任丟給開發者的句子。

## Step A：探索專案既有慣例（撰寫前必做）

用 Grep 找出當前專案對各維度是否已有統一慣例（**樣式通用，依專案命名調整**）：

| 維度 | 探索線索（grep 關鍵字，依專案調整） |
|------|--------------------------------|
| 分頁 | `PagedRequest`、`PagedResponse`、`IPaged`、`pageSize` 基底 |
| 排序 | `OrderBy`、`SortBy`、`BuildOrderBy`、sort 白名單/工具；有無統一追加決勝欄的作法 |
| 日期區間 | `DateRange`、`StartDate`/`EndDate` 驗證或標準化 |
| 匯出 | `Export`、Excel／CSV 匯出函式庫、共用匯出服務 |
| 權限過濾 | 權限/資料範圍 service（如 `*PermissionService`） |
| 效能 | no-tracking、projection、分頁上限設定 |

→ 有慣例：規格引用它（附路徑）。無慣例或慣例不護欄：本功能自定義。

## Step B：DoR 維度基準（依專案增減，非固定清單）

對每個適用端點，逐一解析。**此為常見 baseline，專案可增刪維度**：

| # | 維度 | 必須回答 |
|---|------|---------|
| 1 | **分頁策略** | 預覽分頁 or 全量？預設/最大每頁筆數？預估資料量？預覽與匯出參數是否分離？ |
| 2 | **排序** | 允許排序的欄位白名單？`SortBy 值 → 實際 ORDER BY 欄位序`？預設排序？（若後端無白名單，spec **必須**自列，避免注入） |
| 2b | **排序穩定性** | 排序鍵在資料集唯一嗎？不唯一 → **決勝欄**（不加則分頁會跨頁重複／漏筆）。排序欄可為空 → NULL 位置？字串型編號 → 字面序或數值序？完整規則見 `references/sort-order-standards.md` |
| 3 | **日期邊界** | 區間含端日否？時間部分如何處理？時區？ |
| 4 | **1:N 取值** | 任何「反查/回填/帶入」遇一對多時，取哪一筆（最新/第一/全部/加總）？ |
| 5 | **聚合母體** | 每個 count/小計/統計的母體單位（表頭 or 明細）與 grain？ |
| 6 | **匯出規格** | 欄位順序 / 標題 / 檔名規則 / 數字與日期格式 / 每欄來源 / **排序是否與畫面一致**（不一致要說明）；分組報表的分組鍵序 + 組內序 |
| 7 | **權限過濾** | 資料可見範圍由誰決定？來源表.欄位？legacy / 邊界資料歸屬？ |
| 8 | **效能** | no-tracking？projection？大資料量保護？ |

## Step C：輸出

填入 BFS **§6.0 列表/報表端點規格基準**表（格式見範本）。每維度標 `依循慣例（路徑）` 或 `自定義（值）`。任一維度留空或 hand-wave = 規格未就緒，回頭補。

> 📎 維度 2-5（含 2b）同時餵 SAD §6.6 邊界清單；維度 1/8 對應 SAD §6.5 NFR。
