# 簡單優先

用最少的程式碼解決問題，不寫投機性的東西：

- 不加沒被要求的功能與「彈性」。
- 單次使用的程式碼不抽象化；三行重複勝過過早抽象。
- 寫了 200 行但 50 行能解決，就重寫。

# 外科手術式修改

- 只碰必要的地方，不順手改相鄰程式碼的註解與格式。
- 自己的修改造成的孤兒（import／變數／函式）要清乾淨；既有的 dead code 不動，只提出。

# 目標驅動

- 改第一行前先說出驗收方式：哪條指令、哪個操作或誰來判斷——
  「修 bug」→「寫一個重現它的測試，看它失敗，再讓它通過」。
- 回報時本機測試、build、commit、push、上線各自宣稱，不拿一個代替另一個；
  驗收方式沒實際跑到的需求標「未驗證」。

# 驗證紀律

- **修正輪自己會引入缺陷**：改完先掃兩項——搬動區塊有沒有切斷表格、吃掉標題前的空行；同一條規則的標題、詳述表、流程圖、對照表是否都改到（用編號全域 grep）。
- **AI 寫的彙總數字必回原文驗證**（筆數、區間、連續性、「見 §X」）：錯得通順最危險。自己跑 grep 計數，不採信產出者的數字。
- **一致性改動給判定基準、要求全域掃描**，不給行號清單：點名等於假設已找全。自己改多份文件時也一樣，A 檔改了要掃 B 檔。
- **說「這條無效／不影響」前先確認作用域**：多層設定（user／project／local）在別的環境可能是唯一一道護欄；找一個它會生效的情境反證自己，再找 log 或殘留檔實證。
- **程式規則不等於存量事實**：防呆（「不可停用主要列」）與必填標註只管今後寫入，不代表資料庫裡沒有違例；斷言存量要實查資料。
- **缺席不等於通過**：比對／驗證／閘門工具遇到鍵不存在、null、空輸入要拋錯，不回預設值；比對用權威來源給的期望集合，不用兩邊 union。查回 0 筆先懷疑路徑與鍵名。產機器檔（yml／json）要回報「解析通過」，不是「寫了 N 行」。
- **成敗看 exit code**：驗證跑專案自帶的 script，不自己拼指令；`cmd | grep`／`| tail` 會吞掉失敗碼與崩潰訊息（空輸出不等於通過），要濾先落檔再濾；後面接 `&&` 的關鍵步驟（push 成功才 bump）不接管線。macOS 沒有 `timeout` 指令。
- **防護類改動要實際觸發一次**：hook 只有 exit 2 才攔截，直譯器起不來、編碼錯、未捕捉例外都會靜默放行；權限設定看設定值不算數。改完用無害呼叫觸發一次（含壞掉的情境）。拿掉舊防護前，先證明新防護在開著的 session 都已生效（plugin 是快照，查實際載入的版本，不看來源路徑）。
- **經 `!` 請使用者輸入秘密**：`!` 沒有 TTY，跳提示的指令會收到空字串卻照樣 exit 0。改成先複製、再 `-w "$(pbpaste)"`；存完驗長度與前綴（不印值），不拿下游成功當證據。

# 能力缺口

同一件事換過做法仍失敗兩次、已裝 skill 幫不上（缺專門知識或工具，非程式 bug），或使用者要找現成 skill／plugin／工具時，依序找：

1. plugharbor：開場列為停用、或 `~/.claude/plugins/marketplaces/plugharbor/plugins/` 裡沒裝的，讀 SKILL.md 照做再問要不要啟用。
2. 外部：WebFetch `skills.sh/api/search?q=<關鍵字>` 列候選；要裝就提問提議 `/research:plugin-harvest <關鍵字>`，同意後讀上述目錄的 `research/skills/plugin-harvest/SKILL.md` 照做（不能用 Skill 工具）。

外部的都經它核准才裝；使用者不同意就用現有能力繼續。
