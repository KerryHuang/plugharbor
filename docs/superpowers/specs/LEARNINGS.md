# 實作經驗

## 2026-11-16 demo-video 優化
- 計畫裡寫死的測試期望值要先自己算過：brief 把「Edge TTS 3」算成 7 字，實際 8 字，實作者照公式跑出紅燈才發現。
- 起站就緒不能只看 health check：埠可能被別人的程序佔用，也可能由啟動器的孫程序在聽。要比對監聽者屬於自己起的 process group（Windows 只能比 pid）。
- 收尾函式要冪等並記住同一個 promise：信號處理與失敗路徑會同時呼叫 stop，第二次若立刻 return，程序會提早 exit，留下子程序和鎖。
- 授權或來源標記只寫實際用到的來源：腳本自帶的 TTS 不能沿用配方宣告的 provider 與授權狀態。
- 新測試與修正一起寫、沒單獨看過 RED 時，審查要靠推理確認鑑別力（例如 0.0.0.0 佔埠測試只在 macOS 有鑑別力），並在測試註明適用平台。
